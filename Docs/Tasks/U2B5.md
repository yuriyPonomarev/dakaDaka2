# U2B5 — worn rolled six-attribute bonuses reach the real actor (code saved; every compile/behaviour check pending manager)

- Changed only `Runtime/Stats/StatsComponent.cs`, `Runtime/Player/PlayerRig.cs`, `Runtime/Items/Equipment.cs`. No Inventory/ItemInstance/affix validator/UI/skill/combat/builder/scene/asset/gate/package/meta edit, no new serialized field, no new asset, no test touched.
- New APIs — StatsComponent: `RebuildFromInstances(IReadOnlyList<ItemInstance>)` (distinct name, so no `Rebuild(null)` overload ambiguity), statics `SumFixedBonusesFromInstances`, `SumRolledAttributeAffixBonuses(list)` and `(ItemInstance)`, `SumBonusesFromInstances`, read-only `RolledBonuses` (the rolled half of `EquippedBonuses`, for verification only). Equipment: `WornInstances` — a `WornInstanceListView` (implements `IReadOnlyList` and nothing else, out-of-range throws) over the one authoritative `_gear` array, not a second store; `Slots`/`Equipped`/`EquippedInstance`/`HoldsUid` and U2B4 transfer behaviour unchanged. PlayerRig: private `RebuildAttributeStatsFromGear()`.
- Live path: `Equipment.RefreshStats` → `PlayerRig.RefreshEquipmentStats` → `RebuildFromInstances(equipment.WornInstances)` → `_snapshot.WithBonuses(fixed.Plus(rolled))` → `AttributeRules.Derive`. Each worn slot adds its `Definition.AttributeBonusTotals` once plus its own immutable `AffixRecord`s mapped by the checked `AffixStatKeys.TryAsAttribute` (typed key, no string lookup, no cast); `_snapshot` keeps the pristine class base, so every pass replaces the bonus set — no accumulation across equip/unequip/re-equip and no double count of instance vs definition. Score clamp 1..30 happens in `AttributeScores.WithBonuses`, modifier `floor((score-10)/2)` in `AttributeRules`; HP/mana/stamina/regen/walk-DEX/weapon-scale/CHA-scale all read that one `_derived`.
- `ApplyClass` now rebuilds from currently worn instances immediately after `Initialize(data)` and before `loadout.Apply` (which calls `InitializeVitals`), so a class applied over still-worn gear fills run-start pools from pristine class + that gear once; with nothing worn it is byte-identical to the old behaviour. Existing gates apply a class to a fresh rig, so this is a no-op for them.
- No healing/refill: equip and unequip still only take `SetMax` (clamp-down only) plus `SetRegen` with the run's existing delay — no `InitializeVitals`/`Configure` on any gear path. Movement multiplier+flat order, passives, sprint/crouch authored bases, damage scale and the per-cast CHA snapshot are untouched. Rolled affixes are read only: no reroll, no UID copy/mint, no definition or class asset write.
- Explicitly DEFERRED, not silently ignored: the seven functional affix keys `armor`, `max_health`, `max_mana`, `move_speed`, `melee_damage`, `projectile_damage`, `mana_regen` are not applied by this slice and are not reinterpreted as ability scores — they need their own numeric-affix semantics in the next slice. The legacy `CharacterStatStack` equipment source still carries only each worn definition's authored `StatModifiers`, so a rolled numeric key is applied neither here nor there yet.
