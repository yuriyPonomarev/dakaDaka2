# R6c1 identity-safe inventory screen commands

Status: applied, independently reviewed and accepted by root on 26 October 2026. The external-draft handoff below is retained as provenance.

## Scope

The satchel screen now selects an inventory stack by its nonzero runtime `StackId`. Definition, origin cell, count, and current list index are refreshed display data only. If an external change moves the selected stack or shifts its index, the selection follows that identity and the screen refreshes its current origin/count. If the identity retires, `Rebuild` clears it; another stack with the same definition at the old cell cannot inherit it. Unequip selects the exact returned item by `ItemInstance.Uid`.

Every production mutation initiated by `InventoryScreenController` uses `IInventoryAuthority.TryCreateLocalCommand` and `Submit`: Move, Swap, Merge, Equip, Unequip, and Use. Commands carry the current StackId(s), exact gear UID preconditions, current shared revision from the existing builder, owner, and sequence. Authority refusal keeps a still-live selection and refreshes the screen; a missing selected identity is cleared. Existing click and right-click gestures, toast feedback, and presentation layout are retained. No UI hierarchy, serialized field, prefab, or package changed.

Hotbar binding is explicitly outside this slice and remains R6c2 work; the existing hotbar still addresses current inventory indices 0-3.

## Focused gate additions

`EmberdelveInventoryUiChecks.Run` invokes `StableSelectionTracksIdentity` through the same rendered-rectangle `HandleClick` path as existing UI interactions. The fixture removes an earlier list entry, confirms the selected ID survives at its shifted index, externally moves it, then places a new instance of the same definition at the old cell. A subsequent UI click must move the original StackId/UID while preserving the lookalike. Removing that selected identity and placing another copy at the same location must clear selection; a later empty-cell click cannot move the replacement.

`RightClickUseSubmitsCommand` clicks an unselected healing item through `HandleClick`, then checks the canonical heal amount, exact stack retirement, one revision, and one final inventory event.
