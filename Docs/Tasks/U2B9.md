# U2B9 — chest owns immutable rolled gear; opening transfers same UID (code saved; every compile/behaviour check pending manager)

- Changed only `Runtime/Data/LootTable.cs`, `Runtime/Items/LootPickup.cs` (host contract only), `Runtime/Interaction/ChestInteractable.cs`, `Runtime/Flow/RunDirector.cs` (+ this report). No Inventory/Equipment/roller/instance/stats/UI/builder/scene/asset/gate/package/meta edit, no test touched, no new asset.
- APIs: `LootEntry.affixRarity` (public `AffixRarity`, default `Common`=0, enum values untouched) + `RequestsRolledGear`; `LootTable.affixCatalog` (`AffixDefinition[]`, null/empty = legacy), `AffixCatalogCount`, `RequestsRolledGear`; `LootDrop.Instance`/`IsRolled`/`Rarity`/`UidText` + 3-arg ctor (2-arg ctor and `Item`/`Amount` unchanged); `LootTable.TryRoll(seed,outList,out reason)` and `TryRoll(seed,outList,ItemIdentityIssuer,out reason)`; `Items.IInstanceLootHost.TryCollectLootInstance(ItemInstance,out reason)`; `LootCollection.TryCollectInstance(ILootHost,ItemInstance,out reason)`; `RunDirector` now implements `IInstanceLootHost`.
- Legacy shape preserved exactly: `Roll(seed,List<LootDrop>)` still exists and is a thin wrapper that **logs the refusal** instead of hiding it; the item/amount stream is the old loop on `new System.Random(seed)` consuming the same numbers in the same order, so every pre-U2B9 Common-only table (all three authored tables, all Common gear included) drops exactly what it dropped before, and a Common entry is still one `ItemData`+`Amount` drop on the counted partial path. A table with no rolled entry builds no authority/catalog at all.
- Roll lifecycle: profiles/catalog/rarity/equippability are checked before anything is drawn (`(AffixRarity)3`, a rolled entry with no item, and Uncommon/Rare on carried gear are refusals — never downgraded); the table's own trusted catalog is built from its entry definitions (same object repeated = listed once, weighted entries untouched; two distinct objects claiming one item id = refusal) plus its authored affixes (null entry = refusal, repeats deduplicated); then every selected rolled unit is validated mint-free through `LootRoller.TryRollAffixes` and only after all of them pass is each produced **exactly once** by `LootRoller.TryRoll(definition,1,rarity,authority,random,issuer,…)` — one quantity-1 instance per equippable unit, one UID per unit. Any failure returns false with one reason and publishes **nothing** (output stays empty, no partial staging, no rolled flag).
- Determinism: affix draws use a second generator derived from the same table seed (`DeriveAffixSeed`, consumed in selection order, validation pass and production pass use the same derived seed so the proven records are the built records), so same seed + same table + same catalog ⇒ same affix ids/order/values while UIDs deliberately differ per unit. No raid seed policy changed: the chest still uses the explicit layout-provided seed; a per-run server-owned seed is still a later (U3A) requirement.
- Chest: `Open()` calls `TryRoll` once and only then sets `_rolled` (an invalid profile is a failed open with the reason logged, not a chest that pretends to be empty). A rolled drop is offered only through `LootCollection.TryCollectInstance`; accepted → that exact item removed once and credited once (`TakenCount`/`TakenValue` per unit); refused (full bag, dead/non-running run, duplicate UID, host without the instance contract) → the identical `ItemInstance` object stays in `Remaining` with the same UID/rarity/rolls and is offered again on reopen. There is no fallback to `CollectLoot(ItemData)` anywhere: an unsupported legacy host is an explicit refusal that retains the instance.
- RunDirector: `TryCollectLootInstance` refuses a null instance, a run that is not `Running`, a missing rig/bag, or a dead player, otherwise hands the very object to `Inventory.TryAddInstance` (bag's own rule refuses a UID already carried or worn). No mint, clone, copy or reroll on transfer — the accepted bag stack's instance is the same object the chest rolled. `CollectLoot`/`CollectLootCounted` and the U1C2H counted/remainder path (chest partials and loose `LootPickup`) are unchanged; `LootPickup` still carries definitions only (loose rolled-gear pickup was not in scope).
- Deliberately out of scope / remaining: no authored Uncommon/Rare profiles or affix assets (manager builds the focused temporary-definition chest profiles next), no loose-pickup/death/currency-UID/network/contested-transfer work, no UI rarity/UID display, no cloak/back category resolver (a cloak still needs an explicit `ItemCategoryResolver`), no per-run server seed, and no rolled-gear enemy drops.
