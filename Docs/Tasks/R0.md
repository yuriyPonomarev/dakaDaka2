# R0: extraction rule enforcement + stale AttributeSkill fixture

## Files changed
- `Runtime/Flow/RunDirector.cs`: `BeginExtraction` is now `bool BeginExtraction(out string reason)`. It re-runs `ExtractionAllowed`, refuses with a reason (and raises a toast) instead of completing the run.
- `Runtime/Interaction/ExtractionPoint.cs`: `IExtractionSink.BeginExtraction` signature updated; `OnHoldComplete` re-checks `CanInteract` and toasts the reason if blocked.
- `Runtime/Interaction/Interactor.cs`: when a hold reaches 100% it re-asks `CanInteract` before `OnHoldComplete`, otherwise toasts the reason (progress is already reset). Damage taken (rig health drops) resets hold progress. Leaving range already reset it (target change sets progress 0); unchanged.
- `Runtime/Input/EmberdelveInput.cs`: test seam `bool? InteractHeldOverride` (null = real action). Needed because there was no existing fake for InteractHeld.
- `Editor/EmberdelveRuntimeSmokeTest.cs` (`ExtractionFlow`, also used by ResultLoop): drives the real Interactor hold; now 35 checks (was 24).
- `Editor/EmberdelveAttributeSkillGate.cs`: id `u2a5_warrior_cha-2_cry` -> `u2a5_warrior_chaneg2_cry` (only use); the charm `TryAdd` check now logs the refusal reason in the check label and a LogError if refused. Assertions unchanged.

## New tests (RunExtraction)
Parks enemies (SetActive false, so live hits do not interrupt holds), stands at gate, then: (4) direct `BeginExtraction` with zero loot refused with reason, state Running, no RunEnded; (1) zero loot + full hold via Interactor => stays Running, "relic" toast surfaced, progress reset; add loot; (3) hold half way, `rig.ApplyDamage`, progress drops to <0.2; (2) full hold => RunEnded exactly once, state Extracted.
Why it fails on old code: old Interactor called OnHoldComplete without CanInteract and old BeginExtraction completed unconditionally, so (1) would extract (state Extracted, RunEnded x1), (4) would not compile/refuse, (3) progress would continue (no damage reset). I did not run a reverted build.
Note: during development the first run failed because live enemies hit the player and interrupted the hold (damage interrupt working); fixture now parks enemies.
