- Inventory tabs: two `UiFactory.CreateButton` chips in the existing header band — `TabBag` 94x26 at panel-local x −364..−270, `TabCharacter` 94x26 at x −260..−166, both y 162..188 (header band unchanged, header text now starts at x −156, width 271). Driven by onClick on the accepted canvas GraphicRaycaster + InputSystemUIInputModule; `SelectBagTab`/`SelectCharacterTab` only flip `_showCharacter`, toggle `GridGroup`/`StatsGroup` and recolour the chips.
- Character pane: one contained `StatsPane` image (526x340, panel-local x −364..162, y −188..152) covering the bag column below the header; rows parented in `StatsGroup` parked at its top-left inset (10px padding). 4 section headers (21px) + 13 rows (18px) = 318px ≤ 320 available; label column 168px, value column 338px, fonts 15/14, warm/dark palette, light text.
- Values are queries, never literals: six effective scores + `floor((score-10)/2)` modifiers + worn bonus from `StatsComponent`; HP/mana/stamina current/ceiling/regen from `HealthComponent`/`ManaComponent`/`StaminaComponent`; guard from `PlayerRig.Defense` (`DefenseProfile` block %/arc/shield); walk speed from `PlayerMovement.ResolveWalkSpeed()`; weapon line `baseDamage x PlayerRig.GetOutgoingDamageMultiplier(weapon)` (the authority's own pair, before target defence, no second STR/DEX/passive) shown as `Ashen Short Sword 26 -> 34.9 before armour`; CHA line `StatsComponent.GetAbilityEffectScale()` as "1.12x  Charisma scales skill effects".
- View lifecycle: the view is constructed once in `Build()`, its lines built once (`RowCount==0` guard) and afterwards only re-labelled by `Refresh()`; `Rebuild()` re-points it at the current rig, and `HandlePointer()` refreshes it every frame the panel is open, so class/gear/weapon changes and regeneration show while open, and open→close→reopen cannot duplicate a line or lose the existing InventoryChanged/EquipmentChanged subscriptions.
- Item tooltip: new `Tooltip` Text in the top 20px of the band the instructions already owned (instructions now 32px below it, 4px gap), so the column height — and the grid, header, detail line and five gear rows — did not move. It names the hovered cell/worn slot through the same `TryCellAt`/`TryEquipSlotAt` hit-test the clicks use (selection as fallback), and prints signed bonuses from `ItemData.AttributeBonusTotals` (six allowlist keys only). A tooltip may only name a definition still carried or worn; nothing is selected, moved, equipped or re-rolled.
- Bag tab keeps everything: grid cells, item blocks, selection frame/ghost, all five `Equip_*` rows (visible and clickable in both tabs), detail line (grid/free/value/worn) and instructions. The raw `modifiers: strength=16(+3) hp=120 …` run-in was removed from the detail line because the pane replaces it; bag value moved to the detail line and the header now reads `SATCHEL 12/40 worn 3` so it cannot run under the tabs.
