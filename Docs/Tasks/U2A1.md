# U2A1 — six-attribute pure rules foundation (code saved; compile/run pending manager)

Files added (only these two, plus this report): `Assets/Emberdelve/Runtime/Stats/AttributeRules.cs`, `Assets/Emberdelve/Editor/EmberdelveAttributeRulesGate.cs`. No existing script, test, scene, prefab, asset, package or dirty M5 file was touched; no .meta files were hand-written (Unity imports/generates them).

Behaviour implemented: `Emberdelve.Stats` now owns `SixAttribute` (typed enum), `WeaponDamageScale`, `AttributeLimits` (1..30, modifier anchor 10), immutable `AttributeScores` (clamped on creation, so every read is legal), `AttributeBonuses` (per-attribute totals, `Plus` sums before any clamp), `AttributeSnapshot` (pristine base + current bonus set; `Effective` recomputed on demand from the untouched base, `WithBonuses` REPLACES the bonus set so chaining cannot stack), `DerivedStatBases` (caller-supplied base pools/regen/move — no class lookup, no class detection), `DerivedStats`, and static `AttributeRules`: `ClampScore`, `Modifier` = `(int)Math.Floor((clamp(score,1,30)-10)/2.0)` (true floor, so 9→-1, 5→-3, 3→-4, 11→0, 16→3), `EffectiveScore`, `MaxHealth` (floor 25), `MaxStamina` (25), `MaxMana` (10), `ManaRegen` (0.1), `StaminaRegen` (1), `MoveSpeed` (factor floor 0.5, clamp 2..8, explicit passive multiplier and flat item term), `ScaleDamage`/`MeleeDamage` (STR) /`RangedDamage` (DEX) /`FinesseDamage` (max(STR,DEX), factor floor 0.2), `WeaponDamage(scale, effectiveScores)`, `AbilityEffectScale` (clamp 0.6..1.4), `Derive(snapshot|scores, bases)`, `ClampCurrentToMax` (int/float, never raises a pool), `Key`/`TryParseKey` (six lowercase allowlist keys only). Pure C# only: no UnityEngine/MonoBehaviour/ScriptableObject/asset/scene dependency and no static mutable state, so the same inputs always give the same numbers.

Gate: `Emberdelve.EditorTools.EmberdelveAttributeRulesGate.Run` — headless, no scene/play mode/builders/GameObject/ScriptableObject. 115 fixed assertions in 11 sections, each expected constant derived by hand in the adjacent comment (never produced by calling the implementation): modifier table incl. negative odds and out-of-range inputs; score clamps incl. construction clamping and `EffectiveScore`; warrior 16/10/14/8/10/10 over bases 100/75/90 → 120 HP / 70 mana / 100 stamina / regen 3 / move 4.3; archer 10/16/12/10/14/8 over 80/90/95 → 90 / 90 / 100 / regen 4.0 / move 4.6225; pool floors (25/25/10/0.1/1) at modifier -5 and at the unusual -25; move-speed factor floor 2.15, lower clamp 2, upper clamp 8, flat-item 5.1225 and passive-multiplier 5.547 cases; damage 29.12/26/20.8 plus the 0.2 factor floor at modifiers -25 and -30 (5.2) and finesse in both attribute orders; CHA scale 1/1.4/0.8/0.6/1.4 and archer 0.96; bonus sum-then-clamp, idempotent re-derive, non-stacking `WithBonuses` chain (14→16 not 18), unequip returning exactly 120 HP, CON 30+3 clamping to 30 (HP 200) and CON 1−3 clamping to 1 (HP 50), per-attribute sums, and the unchanged pristine base snapshot; pool clamping with no free refill; key allowlist rejecting `armor`/empty/null.
