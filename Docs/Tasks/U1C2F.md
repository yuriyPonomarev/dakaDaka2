# U1C2F — submillimeter CharacterController motion at high FPS (partial: code saved, checks pending manager)

Changed file (only one): Assets/Emberdelve/Runtime/Movement/PlayerMovement.cs — added private ConfigureMoveThreshold() setting controller.minMoveDistance = 0f, called from Awake (fixes a saved-scene rig serialized at the 0.001 default before its first Move) and from ApplyClass (the single class-application point: RunDirector -> PlayerRig.ApplyClass -> ClassLoadout.Apply -> rig.Movement.ApplyClass, which is also where radius/center/height/groundedRadius are configured and the last point before any Move can run, since Update returns while _class == null).
Behavior: Unity discards controller.Move shorter than minMoveDistance, so at dt~0.0008 the sub-millimetre class-speed steps were thrown away and fed back as controller.velocity == 0, restarting the Lerp(actual,target,dt*11) acceleration every frame — the measured W2sec 0.0265m / D1sec 0.00984m crawl. With the threshold at 0 the same steps are applied and accumulate, so the ramp can actually reach 3.5 m/s.
Unchanged as required: acceleration model (speedChangeRate/Lerp/thresholds), skinWidth, radius, center, height, stepOffset, slopeLimit, gravity, ground/collision masks, class values, dash (MoveDash, dash speed cap, CollisionFlags.Sides early stop), guard and status speed penalties, view-relative direction, and the fact that all locomotion still goes through CharacterController.Move — no FPS cap, no speed change, no teleport, no manual transform movement, no geometry bypass.
No scene YAML, prefab, test, harness, review-bridge, package or engine changes. The existing read-only bridge already samples controllerMinMoveDistance, so the manager can confirm 0 from the same telemetry path.
