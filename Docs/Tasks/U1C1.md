# U1C1 — mouse inventory routing and conserving cursor operations (partial: manager gates pending)

Changed files
- Assets/Emberdelve/Runtime/UI/InventoryScreenController.cs — cursor is now a selection of a stack the bag still owns; clicks are hit-tested against the rendered cell/slot RectTransforms via RectTransformUtility with the owning Canvas camera/render mode; new public HandleClick(screen, rightClick); selection marked in place (dimmed block + selection frame + one translucent ghost), never duplicated. With no pointer device the ghost sits over the stack it names instead of at a stale position.
- Assets/Emberdelve/Runtime/Items/Inventory.cs — added TryMergeStacks(sourceIndex, targetIndex, out reason): moves only the target's headroom, keeps the excess at the source, removes only an emptied source, raises exactly one InventoryChanged, touches no counter and raises no ItemCollected. Nothing else in the file changed.
- Assets/Emberdelve/Editor/EmberdelveInventoryUiChecks.cs (new) — 8 pointer scenarios driven through HandleClick using screen points read from the displayed Cell_x_y / Equip_<slot> RectTransform centres (Canvas.ForceUpdateCanvases + frames after each rebuild). No reflection, no private calls, no cloned assets needed.
- Assets/Emberdelve/Editor/EmberdelveRuntimeSmokeTest.cs — entrypoints/dispatch only: RunInventoryUiFlow() → StartRun("inventoryui"), "inventoryui" added to the lobby-scene selection, and a dispatch branch that runs LobbyFlow then EmberdelveInventoryUiChecks.Run(_rig, _director, Check). Lifecycle, watchdog, Check and unrelated flows untouched.

Behaviour implemented
- PickUp/PlaceAt/ReturnCarriedItem and the stale `_carriedFromIndex` are gone. Selecting removes nothing: same stack, same cell, same count, no notification, no credit.
- Selection is identified by the cell its footprint starts at and re-resolved from the grid before every operation (and each frame while open), so no index survives a mutation. An external removal of the selected stack cancels the selection; an unrelated removal leaves the selection pointing at the same owned stack.
- Empty cell → Inventory.TryMove on the still-owned source (its own footprint may be overlapped). Different occupied shape → Inventory.TrySwap; a refused swap leaves the bag, the selection and the counters untouched and notifies nothing. Same cell/stack → cancel.
- Same definition, stackable, headroom available → TryMergeStacks (partial merge keeps the remainder; a full target refuses). Rearrangement conserves TotalUnits, CarriedValue, UsedCells, stacks, LifetimeCollected and RecoveredValue and raises no ItemCollected.
- Equipment click → TryEquipFromInventory on the selected owned stack (no unowned-definition bypass); wrong slot is refused with an explanation before any call, keeping ownership. Worn-slot click unequips through Equipment and then resolves the returned stack by excluding the cells that definition already occupied, so a duplicate copy is not mistaken for it.
- Cancel (right click or same-cell left click), Close, OnDisable and Configure only clear the ghost: no move, no drop, no SpawnLoot, no collection credit. HandleClick also refuses to operate once the run is no longer Running. Gaps, panel border and off-screen clicks remain no-ops.
