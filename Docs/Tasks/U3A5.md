## What was already true (no code needed, now proved by the final gate)

- Late join: NGO spawn sync already delivers every existing player object at its current server transform; `NetClientProbe` already logs one `owner id=.. views=N ids=..` line and per-view positions. Player ids come from the combat-id counter (never reused), so ids are unique even across removals.
- Spawn choice: `RunDirector.PickSpawnPose` (U3A2) already takes the first layout spawn whose 1.2 m neighbourhood holds no current player (`SpawnOccupied`, flat distance of live rigs), and reuses slots in turn when all are taken. A player who walked away from spawn 0 frees it for the next joiner; the gate recomputes the expected slot independently from the logged positions.
- Disconnect: `NetServer.OnClientDisconnected` already removed the actor (movement, RunDirector session/party seat/registry/sender, despawn) for a graceful quit and for a timed-out killed process alike; the freed seat and slot are reusable at once.

## What changed

### Server (`NetServer`)
Only a log: `_lastRemovedBySlot` remembers the player id of the last actor of each slot (not on shutdown); when a slot is admitted again the server logs `rejoin slot=S newId=N previousId=M (admitted as a new actor; nothing carried over)` right after the `admitted` line (that line's format is unchanged, the earlier gates' regexes still match). Policy is unchanged and documented: a returning slot is a new actor; while the old connection is still timing out the slot is refused `duplicate slot`.

### Lobby Join flow
- `Runtime/Net/NetLobbyBridge.cs` (Runtime, no package reference): `Phase` (Idle, Connecting, Connected, Refused, Left, Failed), `Status` text, `Changed` event, `Register(start, cancel)`, `TryStart(host, address, port, classId)`, `Cancel()`, `SessionSlot` (random `p` + 8 hex, once per process). `IsAvailable` is false until the Net assembly registers, so a build without it shows no panel.
- `NetRules/NetEndpoint.cs` (pure, NUnit `NetEndpointTests`, ~25 cases): `IPv4`, `IPv4:port`, `:port`, `localhost`, empty = `127.0.0.1:7777`; everything else (names, IPv6, bad octets/ports, over 64 chars) is refused with a short reason.
- `Runtime/UI/LobbyOnlinePanel.cs` (assembly `Emberdelve.UI`, which now also references `Emberdelve.NetRules`; acyclic): panel top-left built with `UiFactory` (header, address field, JOIN / HOST / CANCEL, status line; JOIN/HOST swap for CANCEL while connecting). The address field is hand-made (the legacy `InputField` reads the old `Input` class; this project is Input System only): typing from `Keyboard.onTextInput` (digits, letters, `.` `:`, max 32), Backspace with repeat, Enter joins, Escape unfocuses, Ctrl+V pastes. The class is the lobby's current selection (`LobbyController.Selected`). Dev/Editor builds only: `-ember-lobby-autojoin IP:port` arms a Join one second after the lobby is up (the final gate drives the real Join path with it; no mouse).
- `LobbyController`: builds/ensures the panel (`GetComponent` else `AddComponent`, so a lobby scene saved before this slice works without a rebuild), logs `[Emberdelve][Lobby] ready classes=N online=B`, refuses DESCEND while an online connection is Connecting/Connected (never true offline), and returns from `Start` immediately when `NetRole.IsNetworked` (a process started as server/client/host from the command line with the lobby as scene 0: the screen is not built; `skipped: process role is X`). Offline "Start run" is otherwise unchanged.
- `EmberdelveLobbyBuilder` adds the `LobbyOnlinePanel` component to `Lobby_Master` (takes effect when the lobby scene is rebuilt; not required, see above).
- `NetBootstrap` "interactive" mode (`_interactive`, only for sessions started by the panel): `StartFromLobby` assembles the same argument list a command line would carry (`-ember-net client|host -ember-port -ember-slot -ember-class -ember-net-connect-timeout 30 [-ember-address | -ember-listen any]`) and appends the REAL command line last, so a test's quit file, timeouts and explicit slot still apply and win; then it creates the same bootstrap component. Progress is reported to the bridge (`Connecting` -> `Connected` on `connected` / host listening; `Refused` with `refused: <reason>` when the server says no; `Failed` on timeout/transport; `Left` on a lost connection or Escape). Failure, cancel, lost connection and Escape tear the session down and load the Lobby scene again (role back to Offline, pointer unlocked, message shown in the panel); `quit-file` / `autoquit` still end the process with exit code 0 (that is how the gate stops a lobby-started client). A process started with `-ember-net` is never interactive. Once the owned player exists, an interactive session locks the pointer (the command-line clients never did). `Entry()` now also calls `NetLobbyBridge.Register(...)` first; that only stores two delegates (no object, no log, no NetworkManager offline).
- `Emberdelve.Net.asmdef` references `Unity.InputSystem` (Escape).

## Decisions
- Host button shipped (same admission and bootstrap code as the dedicated path, `SpawnActor` host branch from U3A3), but flagged EXPERIMENTAL and not gated: the process gate runs a dedicated server. If the windowed pass finds it broken, remove the HOST button (one line in `LobbyOnlinePanel`) and keep Join + dedicated server.
- Final gate uses a lobby-first player (not the NetBoot proof player) so the offline-retention block and the lobby Join path run on the same build as everything else; `LobbyController` is inert in a command-line network role for that reason.
- The lobby's slot is generated per game session (no save file, no machine id), so two windows on one PC work and a leave/join in one session is a rejoin.
- Escape leaves the session (client or host) without a confirm. Pause is not available online (the pause menu is the dungeon `RunDirector`'s, inactive on clients).
- Free-text address field: IPv4 or `localhost` only (the transport takes a literal).

## Risks / UNCERTAIN (nothing compiled)
- No new NGO API was added. New non-NGO API (Input System 1.14, believed correct): `Keyboard.onTextInput` (`event Action<char>`), `Keyboard.backspaceKey / enterKey / numpadEnterKey / escapeKey / vKey / ctrlKey / leftCtrlKey`.
- Lobby -> NGO scene sync: the client starts in the Lobby scene (loaded by Unity, not NGO) and the server's synchronise event loads Level01 in Single mode; the U3A3 clients did the same from the NetBoot scene, so the same behaviour is expected, but this is the first time the previous scene has UI, a camera and an EventSystem. Watch for NGO warnings about untracked scenes in `client_c.log`.
- Interactive tear-down: `ReturnToLobby` destroys the bootstrap (and NetworkManager) object and calls `SceneManager.LoadScene("Lobby")` in the same frame. NGO's shutdown has completed by then (`FinishQuit` runs after `NetworkManager.Shutdown` finished), but statics (`NetPlayerRig.Spawned`, `CombatRegistry` on a host) rely on the despawn callbacks having run; an error here would show on the windowed pass (Escape / refused / cancel), not in the headless gate (the gate only exercises the quit-file end of a lobby-started client).
- Cursor: an interactive session locks the pointer when its owned player exists and unlocks it when returning to the lobby; command-line clients keep their old behaviour (never lock).
- Escape on the host also reaches the host's own pause handling; the scene is replaced right after, so no effect is expected, but it is untested.
- `LobbyOnlinePanel` layout (340 x 190 px top-left, over the title's empty corner) is untested at other resolutions; the class cards start about 206 px from the top at 1280 x 720.
- Offline probe in `-batchmode -nographics`: the lobby builds its uGUI in headless mode (same as the review build); if `InputSystemUIInputModule` misbehaves without devices the marker will not appear and block both the offline block and client C.
- Scene scan: relies on text-serialized scenes (`%YAML`) and `MonoScript.GetClass()` resolving the classes; both hold for this project's scenes today. A binary-serialized scene fails the check loudly (never passes silently).
- A player built with the older `BuildReview` entry also shows the Online panel (the Net assembly is auto-referenced) but is not guaranteed to contain the generated network prefab catalog; use `BuildNetPlayable` for anything that will join a server.
- The 8 s offline window is a lower bound; the gate waits for the marker (up to 60 s) first.
