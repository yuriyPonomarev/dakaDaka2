# U3C3 - sword parry -> riposte combo (4 Nov 2026)

Status: implemented, uncommitted. Server authoritative; the client sends only the existing block-press intent.

## Rules (as implemented)
- A block made with a SWORD records a parry on the server: "defender P blocked at time T against attacker X". Shields never parry (a shield contributing to the guard, even a shield flagged in data, refuses it). Projectile blocks do not create a parry but a projectile hit cancels one.
- Block pressed AGAIN within `riposteWindow` (inclusive) of that block starts a riposte of `RiposteStrikeCount` sword strikes, each x`riposteDamageMultiplier`. Strikes run on the normal swept-melee path (pattern from `riposteSwingPatterns`, gap `riposteStrikeGap`, cooldown skipped for the strikes).
- Nothing else changes: impact power is NOT multiplied, a strike into a held guard is a normal blocked hit (guard reduction applies, guard is not broken), the opponent's block is not broken by the combo.
- Refused (verdicts in `RiposteVerdict`): no parry, window closed, damage taken since the block, already used (one parry = one riposte), kit cannot riposte (shield / ranged / unflagged), weapon changed since the block, dead, stunned, mid-swing. Forged requests (no sender, another player's session) fail sender authorization. Follow-up strikes: NoGrant, TooEarly (not charged), GrantExpired (gap + 0.5 s grace); damage or stagger cancels the rest.
- Enemies do not riposte. No new net message besides `CombatSwingWire.Riposte` (strike number, display / log only).

## Data (on the weapon assets, defaults in `WeaponData`)
`canRiposte` (false; true on ashen_short_sword, ember_rapier), `riposteWindow` 1.0, `riposteDamageMultiplier` 1.5, `riposteSwingPatterns` (sword {0,1}, rapier {0,0}), `riposteStrikeGap` 0.10. Set by `EmberdelveAssetLibrary.ApplyCombatFlow` and written to the existing assets.

## Compromises
- No HUD cue (no hook). The FP arms replay the swing states.
- No host+client network session for the riposte: the wire is GuardDown -> `SetRemoteGuard` -> `MeleeCombat` -> authority, covered by the gate on the authority plus the existing NetCombat gates.
- A refused or failed swing begin keeps the parry; the holder's guard stays down until the riposte ends.
- `RuntimeSmokeTest.RunCombatFlow` is flaky independently of this slice: the player's rolled weapon differs per run (26 vs 15 base damage, block reduction 0.25 vs 0.82) and the check expects reduction below 0.6 of base.
