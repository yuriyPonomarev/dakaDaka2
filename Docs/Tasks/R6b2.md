# R6b2: player-bound inventory commands

## Scope

This source draft adds immutable Move, Swap, Merge, Equip, Unequip and Use commands. Each payload carries a player ID, nonzero sequence, expected shared inventory revision, stable source/target stack IDs, destination cell or equipment slot, and expected gear UIDs. It carries no ItemData, ItemInstance, heal amount, or ammo amount.

A LocalInventoryAuthority instance binds to one exact PlayerRig, Inventory, and Equipment pair. It checks the requesting rig by object reference and checks the payload owner against the bound rig. If a RunDirector is registered, it delegates admission to the existing canonical actor-running rule. Without one, a live bound rig is supported as a local fixture path; this draft does not add network authentication.

## Validation and mutation policy

Malformed commands and invalid owners are refused before sequence consumption. A structurally valid new sequence is consumed before live-owner, run-admission, revision, stack-ID, UID, and business checks. Replays and out-of-order sequences are refused, and sequence exhaustion never wraps. Current stack IDs and gear UIDs resolve against the server-side model before existing atomic Inventory or Equipment mutators run. A valid same-cell move may be accepted without a revision change.

Use resolves healing/ammo values from the live canonical bag definition. A use with no possible effect, including full health or full reserve ammo, is refused without consumption. The authority silently removes exactly one resolved stack unit, commits the shared revision, applies the effect, and raises InventoryChanged after health/ammo callbacks. A busy guard rejects reentrant authority commands during callbacks. After exact-stack consumption and revision commit, health, ammo, toast, and final inventory notifications are attempted independently; observer exceptions are logged and do not turn the committed command into a reported refusal or skip the final bag notification. The existing TryUseSlot API delegates through this same authority and local sequence allocator.

RangedCombat exposes a narrow internal capacity predicate so an ammo use can detect a full reserve without guessing at private capacity. Existing item data, JSON, equipment stats, and hotbar/UI routing are unchanged.

## Focused gate

The new editor gate covers all six successful command kinds; wrong payload owners; a foreign requester carrying the bound owner ID; dead/extracted rigs; stale revisions; replay/out-of-order and sequence policy after business refusals; zero, unknown, and retired stack IDs; correct and incorrect gear UIDs; full-bag atomic unequip refusal with exact snapshots; heal/ammo success from canonical item definitions; full-resource refusal; index compaction without retargeting; one revision per successful use; and reentrant refusal with callbacks observing the committed bag. A throwing health observer is also exercised; the gate checks the applied heal, accepted result, exact unit/revision change, final inventory event, and that the authority accepts a later command.

## Verification state and limits

This is an external source draft prepared for root review. Unity compilation and gate/regression execution are pending. No network trust boundary, UI/hotbar integration, serialization format, item definition, or combat rule is introduced.

Accepted after independent source review and all10 selected groups (2160 checks / 0 failures). Authority103/0: `Logs/opus_finish_20261024_09_R6b2`. Two fixture defects were proven and corrected without runtime changes: direct Loadout.Apply left rig.Class mismatched, so the fixture now uses PlayerRig.ApplyClass and asserts coherent class/loadout/weapon; the full-reserve refusal retained one bundle before a separate successful-use case added two more, so the latter now starts from an empty bag and explicitly asserts two units before use. Earlier failed logs07/08 remain preserved. Focused gate103/0 proves both refusal and exact successful consume callbacks.

The authority owns consumable effects and keeps a committed use accepted when an outward observer throws, logs the exception and attempts the final bag notice. It does not isolate individual subscribers within the global event bus. Existing trusted index mutators remain for fixtures/internal code; production UI/hotbar command routing is R6c. No remote authentication or networking is claimed.
