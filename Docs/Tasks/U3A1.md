# U3A1: network process harness skeleton (NGO 2.7.0 + UTP 2.6.0, direct IP, no gameplay)

Status: written without compiling or running anything (no Unity/git in the implementer sandbox). Every NGO/UTP call was checked against `PackageRef` (NGO 2.7.0, `com.unity.transport` 2.6.0). `Packages/manifest.json` already pins `com.unity.netcode.gameobjects` 2.7.0; it was NOT changed (transport arrives transitively).

## What was added

- `Assets/Emberdelve/Runtime/Net/NetRole.cs` (Emberdelve.Runtime, no package reference): `NetRoleKind {Offline, DedicatedServer, Host, Client}` and static `NetRole` (default Offline; helpers `RunsSimulation`, `PresentsLocalPlayer`, `IsClientOnly`, `IsNetworked`; `Set` is for the launcher only).
- `Assets/Emberdelve/NetRules/` (`Emberdelve.NetRules`, noEngineReferences, namespace `Emberdelve.Net.Rules`): `NetLaunchArgs` (pure parser), `NetTuning` (protocol 1, tick 30, defaults, log prefix), `NetExitCodes`, `NetConnectPayload` + `NetApproval` (pure approval rule: size, malformed, protocol mismatch, server full).
- `Assets/Emberdelve/Net/` (`Emberdelve.Net`: refs Runtime, NetRules, Unity.Netcode.Runtime, Unity.Networking.Transport, Unity.Collections): `NetBootstrap`. A `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` parses `Environment.GetCommandLineArgs()`. No `-ember-net` => returns immediately: no GameObject, no NetworkManager, no log line, `NetRole` stays Offline. Otherwise it sets `NetRole`, creates `NetworkManager` + `UnityTransport` on a DontDestroyOnLoad object (no scene dependency), `ConnectionApproval = true`, no player prefab, `EnableSceneManagement = false` (U3A2 flips it when scenes sync), tick 30, `NetworkConfig.ProtocolVersion`, payload in `ConnectionData`.
- `Assets/Emberdelve/Tests/EditMode/NetRules/` (own asmdef `Emberdelve.NetRules.Tests.EditMode`, 10 NUnit tests) for parser and approval rules. The existing test asmdef is untouched (the nested asmdef takes this folder out of it).
- Editor: `EmberdelveNetBuilder` (menu `Emberdelve/Net/Build NetBoot Scene`; creates `Assets/Emberdelve/Scenes/Emberdelve_NetBoot.unity`, an empty scene with a camera, built additively so open scenes are not discarded; NOT added to EditorBuildSettings), `EmberdelveNetProofGate`, `EmberdelveWindowsBuild.BuildNetProofPlayer` (new internal method only; `BuildReview` untouched), `Emberdelve.Editor.asmdef` gained a reference to `Emberdelve.NetRules`.
- All new files have `.meta` with fresh GUIDs, checked unique against the tree.

Decision notes: NGO needs no NetworkManager in a scene, so the NetBoot scene exists only so the proof Player has exactly one tiny scene (no lobby/dungeon in a headless server). The regular lobby-first builds do not include it.

## Command line

`-ember-net server|client|host` (also `--ember-net=server`), `-ember-port N` (7777), `-ember-address A` (127.0.0.1), `-ember-listen loopback|any` (loopback), `-ember-slot S`, `-ember-class C`, `-ember-net-max-players N` (9), `-ember-net-autoquit SECONDS` (server: from listening; client: from connected; 0 off), `-ember-net-quit-file PATH` (server/host graceful stop), `-ember-net-connect-timeout S` (15), `-ember-net-disconnect-timeout-ms MS`, `-ember-net-protocol-override N` (test only). Aliases `-ember-net-port/-address/-slot/-class` also work. An invalid value for a known option logs an error and exits 2.
Exit codes: 0 ok, 2 bad args, 10 start failed, 11 connect failed/refused, 12 transport failure, 13 unexpected disconnect, 14 shutdown timeout.

## How root builds and runs the proof

Batch (no GUI Editor holding the project; do not pass `-quit`):

```
Unity.exe -batchmode -nographics -projectPath <project> -logFile Logs/net_proof.log -executeMethod Emberdelve.EditorTools.EmberdelveNetProofGate.Run
```
Optional `-ember-proof-dir <abs dir>` (default `<project>/Builds/net-proof/<timestamp>`), `-ember-proof-reuse-exe <abs exe>` (skip the build). From a live Editor via eval: call `Emberdelve.EditorTools.EmberdelveNetProofGate.Run()` (blocking, a few minutes; it does not call Exit outside batch mode). Order of work: let Unity import and compile first (check for compile errors, especially the first NGO IL post-process), optionally run the EditMode tests, then the gate. Child logs are in `<runDir>/logs/{server,client_a,client_bad}.log`.

## Expected log lines (stable prefix `[Emberdelve][Net][role]`)

server: `boot protocol=1 tick=30 port=P ...`, `listening port=P ...`, `approval id=N approved=True slot=proof-a class=Warrior reason=-`, `client connected id=N total=1`, `client disconnected id=N total=0`, `approval id=M approved=False ... reason=protocol mismatch client=999 server=1`, `shutdown begin reason=quit-file players=0`, `shutdown complete clean=True players=0 exit=0`.
client A: `boot ...`, `connecting address=127.0.0.1 port=P`, `connected id=N`, `shutdown begin reason=autoquit`, `shutdown complete clean=True players=0 exit=0`.
client bad: `rejected reason='...'` (or `connect timeout` after 20 s as fallback) and exit 11.
Gate: `[Emberdelve][NetProof] ok: ...` per check and finally `[Emberdelve][NetProof] PASS checks=N failures=0` (about 30 checks; `FAIL ... failures=M` otherwise). Editor exit code 0 only on PASS.

The gate asserts: player built; free UDP port; server listening; client A connected on both sides, approved; A exits by itself with 0 and clean shutdown; server sees the disconnect; client with protocol 999 refused by the server (log + exit 11, never logged connected); server stops via quit file with exit 0 and clean shutdown; no `error CS` / `NullReferenceException` / `Exception:` / `InvalidOperationException` in any child log; all started PIDs gone. It kills only its own PIDs; any kill (timeout or cleanup) adds a failure.

## Risks / things to verify first when root compiles

1. NGO IL post-processing and `Unity.Collections` / `Unity.Burst` transitive packages: first import after the manifest pin must succeed; if `Unity.Networking.Transport` or `Unity.Collections` are not resolvable asmdef names in the Editor project, fix the references in `Emberdelve.Net.asmdef`.
2. Whether the refused client receives `OnClientDisconnectCallback` with a reason (I rely on it; the 20 s connect timeout is the fallback and still exits 11, but the gate waits at most 40 s, and the `rejected` line would be absent).
3. Shutdown: the bootstrap polls `IsListening`/`ShutdownInProgress` for up to 5 s after `NetworkManager.Shutdown()`; on timeout exit code 14.
4. `Application.Quit(code)` exit code in a Development player in batch mode is assumed to propagate to `Process.ExitCode`.
5. Windows firewall: loopback listen (127.0.0.1) by default; `-ember-listen any` may prompt.
6. `EditorSceneManager.NewScene(..., Additive)` + `SaveScene` in batch; the scene file is generated into `Assets/Emberdelve/Scenes` on the first gate run and should be committed afterwards.
7. The NetBoot-only proof player has no game content; later slices extend the scene list (lobby, dungeon) and give NetBootstrap a scene-load step.
8. NetworkManager is created active and its `NetworkConfig` assigned right after `AddComponent` (the pattern used by NGO's own tests).
