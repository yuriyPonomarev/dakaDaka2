# R10a — immutable effective-stat capture

## Scope

Adds an immutable read-only capture over the current authoritative stat owners. Runtime components are not wired to it yet; the next integration slice will add explicit invalidation and replace duplicate read paths only after parity gates pass.

## Files

- `Assets/Emberdelve/Runtime/Stats/EffectiveStatsSnapshot.cs` and its Unity metadata.
- `Assets/Emberdelve/Editor/EmberdelveEffectiveStatsGate.cs` and its Unity metadata.

## Behavior

`EffectiveStatsResolver.Capture` reads the existing six-attribute result, passive/equipment `CharacterStatStack`, worn instance flat-damage affixes, current status multipliers and resolved defense profile. It does not mutate or retain any input. It keeps current six-score math and `CharacterStatStack` flat/multiplier order, walk's DEX/multiplier/flat order and clamp, authored sprint/crouch formulas, pool ceilings/rates, armor sanitization, and separate melee/projectile flat-damage channels. Current health/mana are intentionally not captured; callers continue to own pool state and must use clamp-only `SetMax` for mid-run changes. No cache invalidation or automatic refresh is claimed in this slice.
