# U3A2: offline-preserving network seams, net player prefab, hosted-run RunDirector

Status: written WITHOUT compiling or running anything (no Unity in the implementer sandbox, and no NGO package source in the tree to grep). Every NGO member used is listed under "Verify first when compiling". Nothing below has been run; the numbers the root agent must reproduce are the existing gate counts (MultiPlayer 134/0 etc.) plus the new `EmberdelveNetSeamsGate`.

Scope: Work items 1 to 5 of "U3A2" in `Docs/Tasks/U3A_plan.md`, binding user decisions (NGO, server-simulated movement + owner prediction, 30 Hz, offline = pure non-NGO path and behaviourally identical, auto parties of 3, late join while Running, disconnect removes the actor immediately, rejoin = new actor, loopback only).

## What changed

### 1. Movement seam (offline behaviour kept)
- `Assets/Emberdelve/NetRules/MoveInputFrame.cs` (new, pure, namespace `Emberdelve.Net.Rules`): `seq, MoveX, MoveY, Yaw, Pitch, Flags` (sprint, jump edge, crouch-toggle edge, guard reserved) + `Create`, `IsWellFormed`, `Quantized()` and the helpers `QuantizeAxis/DequantizeAxis` (sbyte, +-127), `QuantizeAngle/DequantizeAngle` (ushort over the full circle), `WrapDegrees`, `ClampPitch`.
  Placement decision: the plan puts it in NetRules. `Emberdelve.Runtime` therefore gained ONE asmdef reference, `Emberdelve.NetRules`. That assembly is `noEngineReferences`, has no references of its own and is not a package, so the reference direction is acyclic (Runtime -> NetRules; Net -> Runtime, NetRules; Editor -> Net, Runtime, NetRules) and Runtime still has no package reference. In memory the axes stay full-precision floats: quantization is a separate, explicit step (`Quantized()`), so the offline Update path is not changed by it.
- `PlayerMovement`: `public void Step(in MoveInputFrame frame, float dt)` and `public bool ExternalDriven { get; set; }`. `Update()` returns when `ExternalDriven`; otherwise it builds a frame from `EmberdelveInput` (move, `SprintHeld`, `JumpPressed`, `CrouchPressed`) and `Time.deltaTime` and calls the private `StepCore`, which is the old Update body in the old order (crouch toggle, capsule height, grounded check, jump/gravity, Move/MoveDash). Differences, all inert offline: the input reads moved from inside the sub-methods to the top (the three properties are side-effect free), and `Move` treats a non-finite axis as no input.
  - The Update path still steers by the live view transform (`ViewRelativeDirection(raw, Transform)`), exactly as before. `Step` steers by `frame.Yaw` through the new `ViewRelativeDirection(Vector2, float yawDegrees)` (the Transform overload is unchanged and still public for the gates). For a view whose flattened forward is (sin yaw, 0, cos yaw) the two agree.
  - `Step` does not rotate the body or look pivot; applying the frame's aim pose is the caller's job (U3A4, with `PlayerLook` limits). `Step` ignores NaN/negative/infinite `dt` and does nothing before a class is applied.
- `EmberdelveInput`: two test seams `JumpPressedOverride` / `CrouchPressedOverride` (internal, same pattern as `ReloadPressedOverride`; null = the real action). Needed so the gate can drive jump and crouch through the REAL Update path. Not touched by game code.

### 2. `PlayerRig`
- `bool SetNetworkPlayerId(int)`: only on a client-only process, only positive ids, one value for life; returns false (no change) everywhere else.
- `WireRig`: when `NetRole.IsClientOnly` it marks the rig wired and returns before the combat id allocation, `CombatRegistry.Register` and the health/mana/dash event wiring. A new `_registered` flag makes `OnDestroy` skip the matching unregistration. Offline/server/host path is the old code.

### 3. `RunDirector`
- `serverMode` (serialized) / `IsServerMode` (= flag or `NetRole` DedicatedServer or Host) / `SetServerMode(bool)`. In server mode `Start` runs `StartServerRun`: no scene-rig join, no `Cursor` change, containers built, run goes `Running` with zero players. `Player` and `LocalPlayerId` do not fall back to the scene rig in server mode (the old fallback would have woken the deactivated scene rig through `PlayerRig.PlayerId` and registered a phantom combat entity).
- `RemovePlayer(int playerId, string reason, bool destroyRig = false)`: unsubscribes the death hook, removes session and party seat, clears `_local` if needed, `CombatRegistry.Unregister` (which also unbinds the sender), input off, dash cancelled, optional destroy. Idempotent (false for unknown ids). The combat authority prunes its own per-id records for unregistered entities already (its existing prune pass), so it is untouched.
- `TrySpawnNetworkPlayer(GameObject prefab, string classId, out PlayerRig rig, out string reason)` plus overloads taking `bool locallyControlled` and a `CharacterClassData`. Resolves the class against `approvedClasses` (new serialized array, wired by the level builder to the asset library's classes; the fallback class is always approved), picks the first free `playerSpawns` slot (join order = slot order; a slot is free when no current session stands within 1.2 m; faces the map centre), instantiates, strips camera/listener/lights (remote only), clears bag and equipment, then `TryJoin(-1 party)`. Any refusal destroys the instance and unregisters it at once, so nothing is half admitted. A remote rig gets `ExternalDriven = true` and gameplay input off; the host's own player (`locallyControlled`) keeps camera, input and self-driven movement. No NGO type appears in Runtime.
- Online (`NetRole != Offline`): `TogglePause` (now `internal` for the gate) toggles only the local `_paused`/input/cursor/`PauseChanged` event, not `Time.timeScale` and not the run state; `FinishRun`, the local branch of `CompletePlayer` and `OnDestroy` no longer reset `Time.timeScale` (private `ResetTimeScale()` is offline-only); `RestartRun` / `ReturnToLobby` log a warning and return (`SceneFlowAllowed`).
- Run-end audit: removing a player never ends the run, and an empty hosted run stays `Running` (late join). `CompletePlayer`/`FinishRun` already tolerated `_local == null` (every local-only branch is behind `session.IsLocal`).

### 4. Scene roles, spawns, prefab
- `Assets/Emberdelve/Runtime/Net/NetSceneRoles.cs` (Runtime, namespace `Emberdelve.Core`, `DefaultExecutionOrder(-10000)`): offline no-op; any networked role deactivates the scene player rig; Client also deactivates the game master (combat authority, run director, HUD), `Enemies`, `Loot`, `Ember_Gate`; DedicatedServer disables HUD, result screen and feedback components before their `OnEnable`. Runtime rather than Net because it needs only `NetRole` and the Editor builder can add it without referencing the network assembly. `EmberdelveLevelBuilder.BuildNetSceneRoles` creates `Net_SceneRoles` and wires the lists; `BuildRunDirector` also fills `approvedClasses`.
- `DungeonLayoutData.playerSpawns` (list of cells), `MinPlayerSpawns = 9`, `MinPlayerSpawnSeparationCells = 2`, `PlayerSpawnWorld(index)`, and `Validate()` now rejects fewer than 9 spawns, non-walkable, duplicate or stacked (Chebyshev < 2) cells. `EmberdelveAssetLibrary.ApplyPlayerSpawns()` (called from `BuildLayout`, idempotent like `ApplyChestSpawns`, so an existing layout asset gets the data on the next `BuildAll`) writes nine fixed cells in three groups of three: Entry Hall `(4,3)` [= single-player start] `(2,2) (6,3)`; Library `(11,2) (15,3) (11,5)`; Armory `(2,9) (6,9) (6,13)`. Chosen to avoid every authored enemy/chest/loot cell and to be on room floor.
- `Assets/Emberdelve/Net/NetPrefabCatalog.cs` (ScriptableObject holding the prefab) and `NetPlayerRig.cs` (`NetworkBehaviour`). `NetPlayerRig`: `ServerPlayerId` / `ServerPartyId` NetworkVariables (everyone reads, server writes); in `OnNetworkSpawn` the server fills them from the already admitted rig, a client calls `SetNetworkPlayerId` / `AssignParty` and turns its rig into a view (self-driven movement off, CharacterController off so the NetworkTransform can write the transform, look/combat/interaction/hotbar components off; observers also lose camera/listener/lights; owners keep the camera). Roles: `Server`, `HostPlayer`, `Owner`, `Observer`. No RPCs and no input yet (U3A4).
- `EmberdelveNetBuilder.BuildPlayerPrefab` / menu `Emberdelve/Net/Build Net Player Prefab`: opens Level01 additively (read only), saves the PlayerRig straight from the scene object as `Assets/Emberdelve/Prefabs/Net/Emberdelve_NetPlayer.prefab`, then adds `NetworkObject`, `NetworkTransform` (position XYZ + yaw, no scale, interpolate; server authority = the default `AuthorityMode`, deliberately not assigned) and `NetPlayerRig`, and creates/updates `Assets/Emberdelve/Resources/Net/EmberdelveNetPrefabs.asset` pointing at it.
- `NetBootstrap.RegisterPrefabs()` loads that catalog with `Resources.Load` and calls `NetworkManager.AddNetworkPrefab` before the manager starts. NetBootstrap creates its NetworkManager from code, so there is no `DefaultNetworkPrefabs.asset`; the catalog replaces it. It runs only on networked roles (offline logs and creates nothing).
- `Emberdelve.Editor.asmdef` now references `Emberdelve.Net` and `Unity.Netcode.Runtime` (the builder and gate use `NetworkObject`, `NetworkTransform`, `NetPlayerRig`).

### 5. Host in the Editor: deferred to U3A3
Not small: it needs the approval callback to admit and spawn (`SpawnAsPlayerObject`), NGO scene management or a documented "scene is already loaded" path, an Editor launch switch for `NetBootstrap` (command-line args do not exist in the Editor), and the identity table. What U3A2 already provides for it: `NetRole.Host`, `RunDirector` server mode for Host, `TrySpawnNetworkPlayer(..., locallyControlled: true)` for the host's own player, `NetSceneRoles` (Host deactivates only the scene rig), and the `HostPlayer` role in `NetPlayerRig`.

## Gate `EmberdelveNetSeamsGate`
`Emberdelve.EditorTools.EmberdelveNetSeamsGate.Run` (same `[InitializeOnLoad]` + SessionState pattern as MultiPlayer/MovementLifecycle; opens Level01, enters play mode, exits the Editor). Final line `[Emberdelve][NetSeams] PASS|FAIL checks=N failures=M`; mismatches log `[NetSeams] mismatch ...` so `Tools/Run-EmberdelveGates.ps1` flags them. `Run()` first calls `EnsureNetPlayerPrefab` (builds the prefab only if missing), so the saved Level01 scene and data assets must already be rebuilt with this slice (Build Vertical Slice (all)); the gate says so if `Net_SceneRoles`, the class list or `playerSpawns` are missing.

Groups: offline Start unchanged (one local session, party 0, Running, registered rig, bound sender, `timeScale` 1, no NetworkManager, no NetworkObject, setter refused offline); prefab + catalog content (NetworkObject, NetworkTransform flags, NetPlayerRig, whole rig, Resources load); layout spawns (>= 9, walkable, distinct, separated, first = start cell, no collision with enemy/chest/loot cells, floor under each, `Validate` negative probe); frame helpers and `ViewRelativeDirection` equality; Step parity (150 frames, walk/sprint/strafe/jump edge/crouch edge, Update path with `Time.captureDeltaTime` and the recorded per-frame `dt`, then `Step` with the same intent and `dt` from the same steady start, max difference <= 1e-4, plus non-vacuity checks) and `ExternalDriven` and garbage frames; pause and scene flow per role; `NetSceneRoles` wiring and per-role `Apply`; client-only rig view; hosted-run join/remove (refusals leave counts unchanged, three joins with auto parties 0,0,1, distinct ids, spawn order, sender table `BoundCount`, registry, death hook for members and not for removed ones, freed party seat and spawn reused, `destroyRig`, baseline restored, zero players keeps the run Running, late joiner, host's own local player, second local refused).

## Decisions
1. `MoveInputFrame` in NetRules and Runtime references NetRules (see above); the alternative (struct in Runtime) would have forced NetRules to reference Runtime, which breaks its pure-test assembly.
2. Update path steers by the view transform, Step by yaw; parity is proven by the gate, not assumed.
3. `NetSceneRoles` in Runtime; prefab catalog asset instead of a scene NetworkManager prefab list.
4. `RemovePlayer` does not destroy the rig by default: online the NetworkObject owns that (`NetworkObject.Despawn`), and NGO also destroys a disconnected client's player object itself.
5. Server mode includes the Host role, because the host's own player is spawned from the prefab like everybody else's.
6. Class resolution lives in Runtime (`approvedClasses`), with the string id as the only thing a client sends.

## Deferred / known limits
- Host-in-Editor smoke (U3A3, above). Admission, `NetIdentityTable`, input RPCs, sanitizer, tick stepping, prediction (U3A3/U3A4).
- `Step` does not apply yaw/pitch to the body; `NetworkTransform` replicates yaw; pitch NetworkVariable and head/weapon pose come with U3A4.
- Client views have no class visuals yet (no replicated class id; `ClassLoadout` is never applied on a client). U3A3 adds a `ClassId` NetworkVariable.
- A hosted run whose current players have ALL died or extracted ends (existing `FinishRun`), after which `TryJoin` refuses late joiners ("the run already ended") and restart is inert online. Needs a server run-lifecycle decision (U4B/U3A5); not changed here.
- `LobbyController` and the lobby scene flow are untouched (a networked process starts from the NetBoot/Level01 path, not the lobby).
- Joining while a pause is local-only is fine; the `Paused` run state is offline-only now.

## Risks
1. Compile risk: never compiled. See the next section.
2. NetworkObject prefab hash: the `GlobalObjectIdHash` is generated by NGO's editor `OnValidate` when the prefab is saved/imported. If NGO logs "no GlobalObjectIdHash" for the registered prefab at server start, re-save the prefab (rerun the menu item) and import once. The catalog being under `Resources` means every Player build (including the U3A1 NetBoot-only proof player) now contains the player prefab; the handshake gate should be unaffected but re-run it.
3. NetworkTransform with a CharacterController: observers/owner clients disable the controller in `NetPlayerRig`; on the server the controller drives the transform and the NetworkTransform reads it (server authority). The owner currently receives the server transform without prediction (movement stream is U3A4).
4. Gate: `Time.captureDeltaTime` must really fix `Time.deltaTime` in the batch Editor; if not, the gate still holds because it replays the recorded per-frame `dt`. `GameObject.Find` in the level builder relies on the roots being named `Enemies`, `Loot`, `Ember_Gate` (they are).
5. Deactivating the scene rig in `NetSceneRoles.Awake` relies on Unity not running `Awake` for a GameObject that an earlier-ordered `Awake` deactivated during scene load. If a networked process shows a phantom combat entity from the scene rig, that is the cause.
6. Regression surface: `PlayerMovement` and `RunDirector` are hot. Offline paths were kept in the old order; the three RunDirector `Time.timeScale = 1f` resets became `NetRole.IsOffline`-guarded (identical offline).
