# U2B7 — rolled melee/projectile flat weapon damage, authority-owned (code saved; every compile/behaviour check pending manager)

- Changed only `Runtime/Core/GameContracts.cs`, `Runtime/Player/PlayerRig.cs`, `Runtime/Data/WeaponData.cs`, `Runtime/Combat/DamageAndScanning.cs`, `Runtime/Combat/LocalCombatAuthority.cs` (+ this report). No Equipment/Inventory/ItemInstance/UI/skill/intent-struct/scene/asset/builder/gate/package/meta edit, no new asset or serialized field, no test touched.
- New optional typed contract `Core.IDamageFlatWeaponBonusProvider.GetFlatWeaponDamageBonus(WeaponData)`, kept separate from the preserved `IDamageOutgoingProvider` multiplier: flat is never smuggled into a multiplier. `PlayerRig` implements it; `EnemyAgent` and every other non-provider stay untouched and contribute 0.
- Provider order: `weapon == null` → 0; key chosen by the weapon's own channel (`weapon.IsRanged ? AffixStatKey.ProjectileDamage : AffixStatKey.MeleeDamage`); sums `ItemInstance.AffixTotal(key)` over `equipment.WornInstances` (all six slots, null slots skipped, records read only) → `WeaponData.SanitizeBaseDamageBonus(total)`. No strings, no stat mutation, no cache, no Equipment change: the sum is re-derived from the live slots at every read, so equip/unequip/selected-different-UID swap/repeated `RefreshStats` cannot accumulate.
- Authority boundary: `LocalCombatAuthority.FlatWeaponBonus(instigator, weapon)` is read from the registry-resolved instigator in `SubmitAttack` and `SubmitSkill` after every validation check, at the exact point it already reads `OutgoingMultiplier`, and is sanitized a second time. `AttackIntent`/`SkillIntent` were not modified and carry no bonus, so no client can supply one. This is local provider plumbing only — it is not proof of real server authority (U3 pending).
- Resolver (appended optional params, all existing callers unchanged): `Resolve(weapon, intent, hit, target, instigatorMultiplier = 1f, weaponBaseDamageBonus = 0f)` and `ResolveSkill(intent, hit, target, instigatorMultiplier = 1f, effectScale = 1f, weaponBaseDamageBonus = 0f)`. The bonus is used in the weapon path only: `skill.UsesFlatDamage` (BattleCry 14) keeps its own number and gains nothing, while Multi-shot/Piercing scale the boosted base with their own `damageMultiplier` and the cast's CHA scale exactly once.
- `WeaponData.DamageAtRange(float distance, float baseDamageBonus = 0f)`: `boosted = baseDamage + SanitizeBaseDamageBonus(bonus)` is computed **before** the existing falloff branches, which are then reused verbatim on the boosted base (`Lerp(boosted, boosted*falloffMinScale, t)`), so falloff/charge/multiplier/headshot multiply the full boosted base and the bonus is never added afterwards. `SanitizeBaseDamageBonus` maps NaN/±Infinity/negative to 0; `BoostedBaseDamage` falls back to the authored base if the sum would overflow. `baseDamage`, ability and protocol state are never written.
- Zero-bonus exactness: `baseDamage + 0f == baseDamage`, so every pre-existing number is bit-identical — sword 26*1.344 = 34.944, bow@15m 34*1.3216 = 44.9344, crossbow 24, rapier 19*1.12*1.2 = 25.536, BattleCry 14*1.12*1.2 = 18.816.
