# U1C1-R4 — swap destinations may not overlap each other (partial: awaiting manager gates)

Changed file: Assets/Emberdelve/Runtime/Items/Inventory.cs — TrySwap only; no other runtime method, UI, test, scene, asset or package touched.

Behavior: before any mutation/event, TrySwap takes both footprints from EffectiveFootprint (clamped to >=1 cell) and builds the two destination rectangles — first item at secondOrigin with first size, second item at firstOrigin with second size. Existing CanPlace is still called for both destinations with both stacks ignored, so grid bounds and third-party obstruction are unchanged. The new requirement is that the two destination rectangles are mutually disjoint using exclusive upper edges, so footprints that only share a border still swap. On collision TrySwap returns false with a reason naming both placements, their shapes and the overlapping width/height, and touches nothing: no origin, order, stack list, count, cell map, TotalUnits/CarriedValue, lifetime counters or InventoryChanged event.

Manager reproduction traced by hand: 1x3 blade at(0,0) + 2x2 boots at(1,0) on a 10x4 grid — both CanPlace checks still pass (each hole is free once both stacks are lifted), the new pair test sees blade[1,2)x[0,3) against boots[0,2)x[0,2), overlap 1x2 at (1,0)/(1,1), so the swap is refused and origins/units/7 used cells are preserved.

Valid unequal swaps are not rejected: the UI fixture's 2x3 cuirass at(0,0) with 2x2 boots at(4,0) gives destinations [4,6)x[0,3) and [0,2)x[0,1) — disjoint, so the swap still commits with one notification. Equal-shape swaps (smoke test's two 2x2 boots/shield) always keep the two original rectangles, which are already non-overlapping, so they stay legal. The pre-existing cuirass-2x3 vs coin-1x1 refusal still fails in CanPlace before the new test, with its original reason.
