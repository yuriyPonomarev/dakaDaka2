# R10b — effective-stat runtime integration

## Behavior

Added a lazy, rig-owned `EffectiveStatsSnapshot` cache over the existing class, attribute, passive/equipment stack, worn-instance, status, and defense sources. Source version counters make direct mutations visible: `CharacterStatStack` Build/Clear/SetSource, `StatsComponent` Initialize/Rebuild/RebuildFromInstances, and status apply/clear/expiry. Rig invalidation covers class completion and main/offhand defense commits; equipment refresh rebuilds the attribute and modifier sources before final invalidation.

Vitals, base movement speeds, outgoing weapon multipliers, worn melee/projectile flat bonuses, armor, and the public `PlayerRig.Defense` read through the capture when ready. `PlayerMovement` keeps guard, aim, status, combat-flow multipliers, and speed floors outside the snapshot. Unready/no-class paths retain their prior fallback behavior.

Pool behavior remains clamp-only through existing `SetMax` and `SetRegen` calls. No current HP/mana is captured; no regear refill or regen-clock reset was introduced. The existing affine formulas and separate flat-damage channels remain unchanged.

The Effective Stats gate adds focused checks for movement parity, passive/source/attribute mutation invalidation, status apply/expiry/clear, and offhand defense invalidation. Its expiry fixture forces the real expiry branch by setting the private status timer to zero and invoking `Update`.
