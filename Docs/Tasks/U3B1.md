# U3B1 — server skill intent foundation

The first isolated step adds a pure per-connection skill intent gate and EditMode coverage. It accepts only slots 0/1, bounded increasing nonzero sequence numbers and finite server time, limits bursts to four and replenishes four requests per second. Replays, malformed requests and floods cannot be admitted; a well-formed flooded request consumes its sequence to allow recovery. Each connection requires its own gate and disconnect cleanup.

Files: `Assets/Emberdelve/NetRules/SkillIntentGate.cs`, `Assets/Emberdelve/Tests/EditMode/NetRules/SkillIntentGateTests.cs` and their Unity metadata. No RPC or gameplay path uses the gate yet. Ownership, lifecycle, authoritative casting, client feedback, and separate-process proof remain future work; this is not network combat acceptance.

Local foundation review completed: 434 EditMode tests passed, including all four new cases, zero failures/skips/inconclusive; controller reported no source drift. See `Docs/Reviews/LOCAL_U3B1-foundation-20261102.md`. The tester identified integration requirements: server-owned monotonic clock, per-connection lifecycle, one shared sequence across both skills, reliable ordered delivery, separate handling of malformed/replayed traffic, and feedback. Sequence exhaustion and clock discontinuities require an explicit lifecycle policy. Unity removed the pre-existing Standalone `SENTIS_ANALYTICS_ENABLED` define during its batch run; Codex restored the exact pre-run bytes and SHA-256 `4518c7ac69b5304680ae204585f9cf31c25908cb0861f2dd45e4eaf38229a407`. The suite passed on Unity's actual tested configuration without that define; restoring it is not proof of a further run. Gate is still not integrated or proof of multiplayer.
