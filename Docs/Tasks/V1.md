# V1: "Dark and Darker" dungeon look (visual-only slice)

Status: written, NOT compiled and NOT run (no Unity in this environment). Every API call was checked by hand against Unity 6000.2 / URP 17.2; the gate `EmberdelveVisualGate.Run` must be run to confirm.

## What changed
1. Textures (`Assets/Emberdelve/Art/ThirdParty/ambientCG/<Id>/`): Bricks100 (walls, 2048x1024 as shipped), PavingStones142 (floor, 2048), Rock030 (ceiling, 1024), Planks023A (wood, 1024). Per id: `_BaseColor.jpg`, `_Normal.png` (from NormalGL), `_MaskMS.png` (R metalness or 0, G=B=0, A = 1 - roughness), `_AO.jpg`. Plus `LICENSE_CC0.txt` and `manifest.json` (source, creator, CC0-1.0, zip sha256, per-file sha256, modifications). No .blend/.usdc/.mtlx/.tres/preview.
   Extra: `Art/Textures/Flame_Soft.png` (64x64 soft radial sprite, generated, used by the additive flame particles).
2. `EmberdelveTextureImport` (AssetPostprocessor, scoped to the ambientCG folder + the flame sprite): Normal -> NormalMap; MaskMS/AO -> sRGB off (MaskMS alpha kept as data); BaseColor sRGB; Repeat, Trilinear, aniso 8, mipmaps, max 2048. Correct on first import. `EmberdelveVisualSetup.EnsureTextureImportSettings()` re-applies and reimports on every material build as a safety net.
3. `EmberdelveMaterials`: Stone_Floor / Stone_Wall / Stone_Ceiling / Lobby_StoneFloor get BaseMap, BumpMap (+_NORMALMAP), MetallicGlossMap (+_METALLICSPECGLOSSMAP, smoothness scale 0.8-0.9), OcclusionMap (+_OCCLUSIONMAP) and a darker, slightly desaturated warm tint, every build, also when the .mat exists. New `Wood_Planks` (Planks023A), `Iron_Dark` (metal 0.85), `Torch_Flame` (URP Particles/Unlit, additive, HDR colour 2.4/1.1/0.35). A texture that fails to load logs a warning and keeps the flat colour.
4. World-scale UVs: `EmberdelveVisualSetup.ApplyWorldUv` replaces only the MeshFilter mesh of each primitive cube with a unit box mesh (24 verts, bounds identical to the cube) whose UVs are world metres / tile per face (floor 2 m, ceiling 3 m, walls 2 m x 1 m because Bricks100 is 2:1). World position is baked into the UVs, so neighbouring boxes continue the pattern. One mesh asset per box under `Assets/Emberdelve/Art/Generated/LevelMeshes/` (`Dungeon_<box>.asset`, `Lobby_<box>.asset`), overwritten in place on rebuild (stable GUIDs), orphans pruned by prefix. Transform scale and BoxCollider are untouched. Lobby boxes got the same treatment.
5. Torches (`EmberdelveTorchFactory`): the cube sconce is replaced by a procedural wall sconce, still one child named `Sconce` of `Torch_i` (no colliders, shadow casting off): back plate, arm, collar and band (Iron_Dark), tilted handle (Wood_Planks), glowing coal (old Torch_Brush emissive material), `Flame` particle system (Billboard, additive, 55/s, max 40 particles, cone, colour/size over lifetime, noise) with a child `Embers` system (max 12). Point light: colour (1.0, 0.55, 0.25), range/intensity unchanged from the layout (13/9 etc.), Soft shadows, strength 1, near plane 0.1. Lobby torches got the same sconce and Soft shadows.
   `TorchFlicker` extended (hand torch unaffected, all new fields default off): `TorchFlicker.MountOnNearestWall` now also rotates the sconce so local +Z faces away from the wall; with `lightFollowsFlame` the light moves to the flame after mounting (sconce kept in place); `lightJitter` (0.02 m) wobbles the light so the soft shadows breathe. Intensity/range flicker unchanged.
6. Environment (`SetupEnvironment`): ambient (0.02, 0.023, 0.032), exponential fog (0.035, 0.026, 0.02) density 0.055, `Moon_Slit_Directional` kept (name and `RenderSettings.sun`) but intensity 0.05, shadows off.
7. Post-processing: `Assets/Emberdelve/Settings/Emberdelve_Dungeon_Volume.asset` created/updated by code (components saved as sub-assets): Tonemapping ACES, Bloom (threshold 1.0, intensity 0.5, scatter 0.6, warm tint, HQ filtering), ColorAdjustments (post exposure 0, contrast +15, saturation -20, colour filter 1.0/0.93/0.84), Vignette (0.35 / 0.4), FilmGrain (Medium1, 0.2). Global Volume object `Post_Volume_Dungeon` in the dungeon scene, `Post_Volume_Lobby` in the lobby. Cameras (player MainCamera, Lobby_Camera): `UniversalAdditionalCameraData.renderPostProcessing = true`, HDR, SMAA high, dithering.
8. `EmberdelveVisualSetup.ApplyRenderSettings()` (called at the start of both builders): through SerializedObject on PC_High.asset and PC_Low.asset: HDR on, HDR colour grading, additional lights per pixel, additional light shadows on, atlas >= 2048, soft shadows on (quality >= Medium), main light shadows on. Only differing fields are written. Active pipeline: Standalone quality is index 3 = "PC High" = PC_High.asset (already had additional light shadows, soft shadows, HDR, 2048 atlas and an enabled SSAO renderer feature); PC_Low.asset lacked additional light shadows and soft shadows, now enabled. SSAO: only checked/enabled on the default renderer, never added from code. PC_Low_Renderer has no SSAO feature: logged as a warning; add manually if the low preset should have it.
9. Gate `EmberdelveVisualGate.Run()` (log style `[Emberdelve][VisualGate] PASS|FAIL checks=N failures=M`, exits the Editor in batchmode): texture importer types/sRGB/wrap/aniso/mips for all 16 textures; the 5 PBR materials have Base/Bump/MetallicGloss/Occlusion maps and _NORMALMAP; flame material additive + HDR; rebuilds lobby then dungeon; every Floor_/Wall_/Ceiling_ box has a BoxCollider whose centre/size (from transform + collider) equal the min/max the builder was asked for (recorded in `EmberdelveLevelBuilder.LastBoxes`), still non-trigger on the Level layer, with a saved 24-vertex unit-box mesh; a global Volume with the profile, Tonemapping ACES, Bloom, FilmGrain; one torch per layout entry with a point light, shadows != None, TorchFlicker, collider-free `Sconce` with a flame system (20-60 particles); camera renderPostProcessing; hand torch intact; ambient < 0.06, fog exponential density 0.04-0.07, moon <= 0.1 and shadowless; URP assets (HDR, additional shadows, soft, per pixel, atlas >= 2048) and SSAO on PC_High.

## Decisions
- Light range/intensity values are kept from `DungeonLayoutData` (range 7-11, intensity 10-16) instead of forcing 7-8; the layout is gameplay data the gates may depend on. Colour was changed as asked.
- Light moves to the flame at runtime only (Start), editor-time positions are unchanged; the existing smoke check "every sconce touches a wall" still measures the `Sconce` origin, which is unchanged (0.12 m off the wall, 0.3 m sphere).
- Per-box mesh assets rather than a size-keyed cache: UVs include world position, so size alone is not a key. Deterministic names, overwritten in place.
- Scene/asset saving: both builders now call `AssetDatabase.SaveAssets()` before saving the scene, because materials, meshes and the volume profile are modified through the AssetDatabase.
- No .meta files are shipped; Unity creates them. The postprocessor makes the first import correct.
- Editor asmdef now references `Unity.RenderPipelines.Core.Runtime` and `Unity.RenderPipelines.Universal.Runtime`.

## Not verified (needs a Unity run)
- Compilation. Points to watch: `VolumeProfile.Add<T>(bool)` / `TryGet`, the post-processing parameter fields (`Bloom.highQualityFiltering`, `Vignette.rounded`, `FilmGrain.response`), `UniversalAdditionalCameraData.dithering/antialiasing/antialiasingQuality`, `ScriptableRendererData.rendererFeatures`, `ScriptableRendererFeature.isActive/SetActive`.
- URP serialized field names used in `ApplyRenderSettings` (taken from the existing PC_High.asset YAML: m_SupportsHDR, m_ColorGradingMode, m_AdditionalLightsRenderingMode, m_AdditionalLightsPerObjectLimit, m_AdditionalLightShadowsSupported, m_AdditionalLightsShadowmapResolution, m_SoftShadowsSupported, m_SoftShadowQuality, m_MainLightShadowsSupported). A missing field only logs a warning.
- Look: torch intensities were tuned for the old flat materials; with darker textured stone, ACES and soft shadows they may need re-tuning (layout data). 10 shadow-casting point lights are the main cost; the 2048 additional-light atlas is shared. Soft shadows near the flame (light 0.4 m from the wall) may need bias tweaks (`light.shadowBias`).
- Existing gates: I grepped the Editor gates for Torch / Moon / Light / Volume / CreatePrimitive / Floor_ / Wall_ and found no assertion on light shadows, moon intensity or torch positions; the only torch assertion is the smoke test's "Sconce touches a wall" (preserved). TorchFlicker still uses `Random.value`, so the LootPipelineGate allowlist stays valid.
- Flame look (particle sizes/HDR) and bloom strength are first guesses.
