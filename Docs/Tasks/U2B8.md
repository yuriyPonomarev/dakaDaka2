# U2B8 — physical armor rating from fixed and rolled equipment (code saved; every compile/behaviour check pending manager)

- Changed only `Runtime/Data/SkillData.cs`, `Runtime/Items/Equipment.cs`, `Runtime/Core/GameContracts.cs`, `Runtime/Player/PlayerRig.cs`, `Runtime/Combat/DamageAndScanning.cs` (+ this report). No ItemData/WeaponData/authority/intent/skill/UI/inventory/builder/scene/asset/gate/package/meta edit, no new serialized field or asset, no test or expectation touched.
- Vocabulary: `SkillStat.Armor = 9` appended after the preserved 0..8 values (every already-authored modifier keeps its number) plus the `HumanStat` label "armor". It is a flat rating only — not a pool, not a multiplier, never `BlockReduction`. No existing asset authors Armor, so every existing item still contributes rating 0.
- Mapping (one point): `Equipment.TryNumericStatTarget` now maps `AffixStatKey.Armor -> SkillStat.Armor` Flat, so `RefreshStats` puts each worn definition's authored Armor modifiers **and** that instance's rolled armor records into the same wholesale-replaced `CharacterStatStack.EquipmentSourceKey` — summed once per worn slot, exact across equip/unequip/different-uid swap/repeated refresh, gone when the slot empties; a non-finite rolled value is skipped like the other numeric keys.
- Provider: new optional `Core.IArmorRatingProvider.GetArmorRating()` — no armor claim in `AttackIntent`/`SkillIntent`, an attacker's own rating is never consulted. `PlayerRig` implements it as `DamageResolver.SanitizeArmorRating(Stats.Flat(SkillStat.Armor))`: the fixed+rolled sum read live per hit, no cache, NaN/±Infinity/negative → 0, no stat stack at all → 0. `EnemyAgent` and every other non-provider untouched → rating 0.
- Finalize order (everything before it unchanged): `max(1, amount)` info → existing `IDefenseProvider` guard through `WithReduction` → then **only** when `info.Type == DamageType.Physical` and the target is an armor provider, `ApplyArmorRating(info, rating)`. A 0 rating returns the same struct untouched (exact no-op), so zero-armor combat is bit-identical.
- Equation: `final = max(1, postGuardAmount * 100 / (100 + rating))` evaluated in `double` (100 + a rating near `float.MaxValue` cannot overflow there; the ratio is never >1 so the cast back to float cannot overflow either). NaN/±Infinity/negative rating → 0; an amount already NaN/±Infinity is returned unchanged, so armor never manufactures a valid hit and `DamageInfo.IsValid`/authority rejection is unchanged. `WithReduction` is **not** reused: armor never sets `Blocked` and never rewrites `BlockReduction`; Blocked/Headshot/BlockReduction/point/direction/source position/source combat id/source kind/type are carried through. No validation bypass, no health write, no refill side effect — the returned Amount is the number `ApplyDamage` subtracts, so reported damage and health lost are one number.
