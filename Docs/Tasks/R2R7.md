# R2/R7 multiplayer authority repair

## Changed

- `Assets/Emberdelve/Runtime/Flow/RunDirector.cs`: session resolution now requires both a registered player ID and the exact admitted `PlayerRig` reference. An arbitrary `IInteractionActor` can no longer borrow an admitted ID while supplying its own alive state, origin, or inventory to loot/extraction authority calls. Interaction admission reports a dead actor before an ended run/session when both apply. It also offers explicit trusted-host class selection overloads for `TryJoin` and `SpawnPlayer`; the compatibility overloads still use the run's selected/default class, while each admitted session records its own class.
- `Assets/Emberdelve/Runtime/Interaction/InteractionRules.cs`: interaction reach sources are finite and positive before use; validation rejects non-finite explicit reach, actor origin, target point, or computed distance. Added an optional generic host admission interface checked before geometry.
- `Assets/Emberdelve/Runtime/Interaction/ChestInteractable.cs`, `LootPickup.cs`, and `ExtractionPoint.cs`: host admission is checked by `CanInteract` before state mutation or loot transfer. Hosts without the optional admission interface keep geometry-only behavior for focused test/fake setups.
- `Assets/Emberdelve/Editor/EmberdelveMultiPlayerGate.cs`: replaced one-frame ranged-hit assumptions with an authority launch at the rig's real muzzle and aim, followed by bounded in-flight stepping through `AdvanceProjectiles`. Rival, party-friendly-fire-off, and friendly-fire-on health assertions remain. Added forged same-player-ID actor checks for loot/session/extraction/chest, non-finite origin/reach checks, null explicit-class rejection, and a mixed Warrior/Archer session assertion.

## Scope note

The explicit class overload is a trusted host/offline API. Network class IDs still require validation against the server's approved class catalog at the network request boundary; this slice does not add that boundary. The admitted-actor identity check plus optional interaction admission protects host-driven interaction side effects before a chest can roll/open or loot/extraction can proceed.
