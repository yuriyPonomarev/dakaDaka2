# U1C1-R3 — inventory controller host stays active

**Changed:** `Assets/Emberdelve/Runtime/UI/HudController.cs`, `BuildInventoryScreen()` only — removed `screenObject.SetActive(false)` on the `Emberdelve_InventoryScreen` controller host (a freshly created GameObject is already active), replaced by a lifecycle comment.

**Effect:** the controller stays enabled, so `OnEnable` bag/gear subscriptions are not immediately undone by `OnDisable`, and the HUD's per-frame `UpdateInventoryScreen()`/`HandlePointer()` has a live component findable without an inactive-search workaround. Subscriptions now end only when the real host is disabled/destroyed (HUD/canvas teardown).

**Preserved:** `InventoryScreenController.Build()` still sets its visual `_root` inactive, so `Open()`/`Close()` alone control visibility — no satchel at startup, no duplicate canvas/screen, no hierarchy/layout/test/engine changes.

**Checks run:** none (file tools only). Compilation, the inventoryui smoke run (previously 22 checks / 1 failure / exit 1 on "the HUD built the satchel screen at runtime") and the sequential items gate are pending manager, as is visual confirmation the panel appears only on I/Tab.
