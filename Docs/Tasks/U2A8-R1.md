# U2A8-R1 — warrior regen failure: diagnosis + fixture isolation (no Unity run performed)

**Proven from source (fixture defect, not a proven runtime bug).** `WarriorSkillFlow` re-enables `cryTarget`
6m ahead for the slow/chase measurement and never parks it: after the chase checks the only cleanup is
`RestoreClearedCorridor()` (loot only), so a live hostile agent stays ~3.8m from the caster through the
~12s `WaitUntil` on both cooldowns, the mana-refusal test and the 4.5s regen measurement. `ManaComponent.Update`
ticks on `Time.deltaTime` and `SkillCaster.HandleDeath` (via `PlayerRig.OnPlayerDied`) calls
`ManaComponent.SetRegenerationActive(false)`, so a caster killed mid-window freezes the pool at exactly the
spent value — matching `40 -> 40` while `RegenDelayRemaining > 0` still passed. The archer flow already parks
its volley/piercing targets ("must not chase the player during later tests"); the warrior flow did not.
The manager log proves the caster was alive at the refusal test (reason `not enough mana (needs 24)`, not
`dead`), so death — if it happened — happened inside the 4.5s window; that branch is **not proven**, and a
paused clock / pool-ceiling change / second pool remain unexcluded because the old fixture logged none of them.

**Changes (Assets/Emberdelve/Editor/EmberdelveRuntimeSmokeTest.cs only).**
1. After the actual slow/chase/damage assertions: `ParkEnemyFar(cryTarget, "the cry target must not chase the
   player during the cooldown and mana measurements")` — existing convention, enemy still a live combatant.
2. Living precondition before the mana-refusal test: `!_rig.IsDead` with HP.
3. Before/after the regen wait: assertions on `!_rig.IsDead`, `mana.RegenerationAllowed`,
   `mana.enabled && gameObject.activeInHierarchy`, single-pool identity (`_rig.Mana` == harness pool ==
   `caster.GetComponent<ManaComponent>()`, `GetComponents<ManaComponent>().Length == 1`), `Time.timeScale > 0.9`,
   and scaled-vs-unscaled elapsed ≥ `manaRegenDelay` (measures the unscaled-wait vs scaled-tick basis
   instead of silently changing it).
4. New read-only helper `ManaRegenDiag` logs one line before/after: mana/max, pool instanceID vs rig/caster
   pool + pool count, component enabled/active, RegenAllowed/rate/delayRemaining/IsFull, HP+dead, RunDirector
   state, timeScale, scaled+unscaled elapsed, live-enabled enemy count and nearest live enemy distance.
   No reflection, no writes, no revive/refill/regen-forcing, no tolerance change.

**Unchanged:** `mana.CurrentMana > afterSpend + 0.5f` and the no-overshoot check keep their original form and
tolerances; the death-no-regen coverage in `DeathFlow` (lines ~1071-1076) is untouched; archer flow untouched.

**Checks executed:** none (file tools only). Manager must rerun `combat`, then the stopped modes
(archer/lobby/resultloop/inventoryui). If the regen check still fails, the two `mana regen diag` lines plus the
new named preconditions identify which branch it is; U2A8 is not accepted by this report.
