# D1c4: enemies attack through the swept melee authority

Scope: the Hollow Servitor's claw and the Ashen Warden's maul stop using the instant, arc-less `SubmitAttack` path. A real `EnemyAgent` is now a swing-pose provider and begins an authority-owned swept swing (the same `TryBeginMeleeSwing` / `StepSwings` / hit-location machinery the player uses). The telegraph wedge is the ground projection of that swing pattern. Nothing was compiled or run (no Unity or git in this environment): every change below is reasoned, not executed. Gate counts are counted by hand.

User decisions applied: (1) enemies move to real swept attacks; (2) the telegraph draws the pattern arc instead of an independent wedge; (3) brain timings are unchanged (minimal option): the swing begins when the brain requests the attack at the end of its windup, with a short pattern windup 0.10 s and active 0.18 s, so damage is accepted about 0.1-0.28 s after the telegraph ends.

## Changes
1. `Runtime/Data/SwingPatternData.cs`: `YawRange(out min, out max)` (min / max key `bladeYaw`, 0/0 without keys). It is the single source of the telegraph angle.
2. `Runtime/AI/EnemyAgent.cs` (mixed CRLF/LF kept): implements `IAimPoseProvider` (eye = `AttackOrigin` = root + 1.2 m, yaw = the direction latched at swing begin, otherwise the brain's committed telegraph direction, pitch 0). New: `AttackPattern`, `TelegraphReach` (pattern `EffectiveReach`), `TelegraphHalfAngle`, `LastSwingId`, `SwingsBegun`, `IsSwinging`, `TryBeginAttack(flatDirection, out reason)`, `IsStunned`, `SetStunned`. `Update`: the brain's `RequestAttack` calls `TryBeginAttack(TelegraphDirection())`; the agent stands still while its swing runs; `PollSwing()` reads the authority's status, flags a whiff when the swing reaches Recovery with no hit (not when it was ended by death or stun). The telegraph stays lit through the windup and the swing's own windup and active phases. `ActiveWeapon` is null while stunned. `HandleDeath` clears swing state. The old `SubmitAttack` / `TelegraphLength` / wedge test are removed. `LootPipelineGate` source greps still hold (no random sources, `DropEnemyLoot(` present).
3. `Runtime/AI/EnemyBrain.cs`: `IsStunned`, `SetStunned(bool)` (Stunned state holds still, winds nothing up, requests no attack; releasing returns to Chase; ignored when Dead). Nothing in the game stuns an enemy yet; this is the seam, and the new gate pins the swing cancel through it.
4. `Runtime/Combat/AttackTelegraphVisual.cs`: `Create(owner, minYaw, maxYaw, color)`; the old `Create(owner, cone, color)` delegates (symmetric). Exposes `MinYawDegrees`, `MaxYawDegrees`, `HalfAngleDegrees`, `LastLength` (radius last passed to `SetState`).
5. `Runtime/Data/EnemyData.cs`: `attackTelegraphCone` tooltip only (cone = pattern yaw range, authored into the pattern by the data build). No new `EnemyData` field: the pattern is found through `attackWeapon.swingPatterns[0]`.
6. `Editor/EmberdelveAssetLibrary.cs`: `ApplyEnemySwings()` after `BuildEnemies()` in `BuildAll`; `AuthorEnemyPattern(...)`. Code-authoritative and idempotent like the player patterns (`LoadOrCreate` + field rewrite every build).
7. `Editor/EmberdelveEnemySweepGate.cs` + `.meta`: new gate (see below) and `EnemySweepPredictor` (shared with `AttributeSkillGate`).

Both patterns are one combo step at multiplier 1 with no impact zones, so the only damage variance is the hit-location table (head 1.5, body 1.0, arms 0.8, hands 0.7, legs 0.6, feet 0.5). Enemy hit volumes use scale 1 (elite 1.25), the attack eye is a constant 1.2 m for both.

Asset files: the tree contains no `.asset` / `.meta` data files at all (they are generated in the Unity project by the library at build time), so there is nothing to copy; `Pattern_ClawSlash.asset` / `Pattern_MaulSweep.asset` are created and wired to `Weapon_HollowClaw.asset` / `Weapon_WardenMaul.asset` by `ApplyEnemySwings()` on the next `EmberdelveAssetLibrary.BuildAll`. The plan's name `Pattern_MaulOverhead` was changed to `Pattern_MaulSweep` because the pattern is a horizontal sweep, not an overhead. The plan's `attackTurnRateDuringSwing` idea is dropped: the pose yaw is the latched direction, independent of the body turn, so a turn limit would add nothing.

## Legacy path
`LocalCombatAuthority.SubmitAttack` already refuses a melee weapon from any instigator that is an `IAimPoseProvider` unless the internal `AllowLegacyMeleeAttacks` probe is on (`"melee attacks from this instigator must begin a swept swing"`). A real `EnemyAgent` is now such an instigator, so its legacy claw path closes with no authority change. Pose-less fakes (the SweptMelee `PoselessAttacker`, CombatFlow dummies) stay on the legacy path.

## Risks
- Not compiled. Likeliest compile points: `EmberdelveEnemySweepGate` (fake player interfaces `IGuardBreakDefender`, `IStatusTarget`), the `AttackTelegraphVisual` overloads, CRLF/LF mix in `EnemyAgent.cs`.
- The real-level smoke fixtures (ai, DefenseFlow) depend on level geometry: a wall within about 2.7 m inside the 120 degree arc stops the blade (`WallStop`) and deals nothing. OffAxisWindup now searches for a clear arc and fails with a diagnostic if none exists; `ai` (9 s window, about 3 attacks) only asserts some damage.
- Location variance: the claw can land on arms (x0.8) or head; fixtures predict it rather than assume Body. The elite's eye is a constant 1.2 m while its volumes are scale 1.25; its swing is level at 1.2 m.
- Difficulty: the player gets the telegraph plus 0.28 s of sweep before damage lands (brain timings unchanged by decision). The wedge stays lit through it.
- Cleave: `maxTargets` 2 lets one swing hit two players in the arc.
- The weapon assets' old `windupTime` / `activeWindow` / `recoveryTime` fields are no longer read by the swept path (left as they were; D1c5 can dedupe).
- `HitSlowsApplied` / guard break on monsters hitting players now go through `ApplyHitEffects` (the maul's hit slow and guard-break stagger now reach players hit by monsters; check this is the wanted difficulty).

## Run 1 fixes (4 gates failed, compile clean)
- EnemySweepGate "maul: the slow lasts about 1.5 s": fixture timing, not a runtime bug. The status ticks down in real time during the 0.5 s recovery, so it was read at about 1.0 s. Now read at the instant of the hit (> 1.2 s, <= 1.5 s).
- SweptMelee "claw swing at nothing": the claw fixture shared its eye with bodies left by the earlier ForgedIntents scenario (hostile to the player-team Swinger), so the swing legitimately hit one. The claw Swinger now stands 500 m away from every other fixture.
- AttributeSkill claw hits: the predictor is correct (EnemySweepGate pins it on static volumes and passes) but the claw's contact on a centre-line target is a knife-edge Body/Arms decision (simulated depth difference under 5 mm; the winner flips with the sample count and a 3 cm height difference). The gate now takes the factor from the location the authority reports (15 x literal factor), requires Body or Arms, and only logs the prediction.
- Smoke OffAxisWindup +-45: the player started at the anchor, which can be several metres from the enemy's start cell, so the enemy walked to about 2.2 m before winding up and swung from a position whose arc and strafe spots had never been checked (a wall can stop the blade). The player now starts at the 1.8 m standoff, the enemy does not walk, and the arena check covers that start spot plus the swing arc from the real position. The diagnostic now prints the swing's end reason, wall sample and sample progress. If it still fails, that line says whether the blade was wall-stopped.
