# U2B11: Back/cloak slot, cloak data, rarity + fixed/rolled tooltips, complete character pane

Implemented and verified in batch mode (Unity 6000.2.5f1, one process at a time). Nothing committed. Persistence, networking and art are untouched.

## Design
- `EquipmentSlot.Back = 6` is appended (existing values unchanged, assets store the integer). `ItemCategoryRules` maps Back to `AffixCategory.Cloak`, so a cloak instance rolls Cloak-category affixes through the default resolver (the builder's affix catalog already allowed Cloak on the 6 attributes, armor, max health/mana, mana regen and move speed; melee/projectile damage stay Weapon only).
- `Equipment.SlotCount` is now `public static readonly`, derived from the highest enum value (`7` = None + six slots). All loops (`HoldsUid`, `IsEquipped`, `Clear`, `RefreshStats`, `Describe`, `RecomputeSlots`, `SlotIndex`, `WornInstances`) use it. `InventoryScreenController.SlotOrder()` is derived from the enum too. Equip/unequip/swap, atomic bag transfer, the stat recompute from pristine class data, armour and attribute flow are the existing code paths: the Back slot is just another index, so a cloak flows through the same paths as chest/legs.
- Two data-defined cloaks, created by `EmberdelveAssetLibrary` (`LoadOrCreate`, idempotent like the other items), both `Back`, `Armor`, 2x3, single:
  - **Ashen Cloak** `ashen_cloak`: fixed Armor +2 (flat `SkillStat.Armor`), fixed Wisdom +1.
  - **Emberthread Mantle** `emberthread_mantle`: fixed Armor +1, fixed MaxMana +15 (flat), fixed Intelligence +1.
  `ApplyAttributeDefinitions` also re-asserts their fixed attribute bonus like it does for cuirass/boots.
- Loot: new `ApplyCloakLoot()` appends one entry per chest table, only if the table has none for that item reference (so a rebuilt project and a fresh clone end in the same table): Supply gets Ashen Cloak (weight 1, Common), Ember gets Emberthread Mantle (weight 2, Uncommon), Sealed gets Emberthread Mantle (weight 2, Rare). Rarity per entry is set by `ApplyLootRarityProfiles` (by item reference). Appended at the END: existing entry indices, items, amounts, weights, maxCopies, maxRolls and the layout's chest seeds are untouched.
- Tooltips: new `Runtime/UI/ItemTooltip.cs` (`ItemTooltipModel` + builder). `ItemTooltip.ForInstance(ItemInstance)` gives rarity name and colour (Common grey, Uncommon green, Rare blue), slot, a FIXED PROPERTIES section from the base definition (weapon base damage, authored modifiers with `Armor` shown as "Armour +N", authored attribute bonuses) and a separate ROLLED AFFIXES section with each rolled record (`+4 armor`, `+0.07 move_speed`), plus a short uid. A Common instance has no rolled section and no header. `ToPlainText()` is what the gates assert on. `ForDefinition` covers carried stacks that have no identity (no rarity, no uid).
- `InventoryScreenController`: tooltips are keyed on the `ItemInstance` under the pointer (bag slot `Instance`, `Equipment.EquippedInstance`, or the resolved selection), not on `ItemData`; `ShowTooltipAt(Vector2)` is the public hover entry (the HUD pointer path calls it) and returns the model, `CurrentTooltip` exposes it. The one-line strip shows the headline coloured by rarity; a new floating `TooltipPanel` (not raycastable) shows the full model, clamped inside the satchel panel. Rebuild re-validates the hovered instance by uid (`HoldsUid`/`HoldsInstanceUid`).
- Equipment column: Back is the sixth row. To keep the panel contained without growing it, `EquipSlotSize` 64 -> 54 and `EquipSlotGap` 8 -> 6: column height 6x(54+6)-6 = 354 px inside the panel's 398 px inner height (was 5x72-8 = 352). The panel (760x430 at -40,20, no scaler) is unchanged.
- `CharacterStatsView`: the six attribute rows already show effective scores + `worn +N`; added an `Armour` row (rating and the 100/(100+rating) share of physical damage) under GUARD (`GuardRowCount` 1 -> 2). Pane arithmetic (review M1): 4 sections x 21 + 14 rows x 18 = 336 px of content, which starts at the group origin; the original 340 px column-derived pane left no margin once the 10 px top padding is counted (346 px). The pane height is now `max(column height, CharacterStatsView.PreferredHeight + PanePadding)` = 346 px, and the inventoryui scenario asserts the last row's rectangle lies inside the pane background and the pane inside the satchel panel.

## Behaviour verified
Gate `EmberdelveCloakSlotGate.Run` (10109 checks): phase 1 (edit mode) runs `BuildDataOnly` twice: both cloak GUIDs stable, every `.asset/.meta/.inputactions` under `Data` byte-identical (SHA1) after run 2, each cloak id exists once, each table holds its cloak entry exactly once (5/5/4 entries), tables validate clean. Phase 2 (play mode, real level rig): slot values/derived count, Back -> Cloak, equip rare cloak -> armour = fixed 2 + rolled 4 = 6 and Wisdom = base + fixed 1 + rolled 2, nothing else moves, no heal/mana refill, repeated `RefreshStats` adds nothing, unequip restores armour, six scores and both pools exactly, 5 extra round trips accumulate nothing, uid/rarity/rolls snapshot unchanged, no mint/credit; mantle fixed +15 max mana, rolled +10 on top, ceiling raise pays out no current mana; boots + cloak together; armour through the real `LocalCombatAuthority.SubmitAttack` path (bare 15, rare cloak 15x100/106, Holy unaffected, unequip back to 15, health delta == DamageInfo.Amount, not flagged blocked); atomic swap: a 4x3 worn cloak vs a 2x3 incoming in a full bag is refused, both cloaks stay, counters/armour unchanged, no notification, full-bag unequip refused; a same-footprint swap replaces (armour 6 -> 2, not 8) and conserves both uids; loot: 3 tables x 400 seeds, every cloak drop is a qty-1 instance with the entry's rarity, Cloak category, 0/1/2 distinct affixes, each affix allowlisted for Cloak (no weapon-only keys), values valid (common=123 uncommon=292 rare=400 drops, 11 distinct keys). The gate's same-seed check only compares drop counts; real determinism of rolls is asserted in the AffixProfile gate; tooltips: three instances of one base give three different texts, rarity names/colours distinct, identical fixed lines, rolled lines only in the rolled section, FIXED before ROLLED, Common has no affix section, uids differ, weapon base damage listed as fixed, coin has no rarity; character pane with a rare cloak worn shows WISDOM effective score with `worn +3` and Armour 6, restores on unequip.
Smoke `inventoryui` (202): new scenario renders six `Equip_*` rows and labels all inside the satchel panel, panel inside 1280x720 and 1920x1080 windows (from its extents about the window centre), hover on two same-base cloaks gives different models and a tooltip panel inside the satchel panel, wrong-slot refusal keeps the selection, Back click wears the selected instance (not the first ashen in the bag), hovering the worn slot shows the same text, right-click take off / swap conserves uids and armour.

## Balance consequence (review M2, not changed)
The weight of the new loot entries has little effect, because tables draw without replacement over single-copy entries. The Sealed chest (3 rolls over 4 single-copy entries) now ALWAYS drops the Rare Emberthread Mantle (rare=400 of 400 seeds, weight 2 is irrelevant), Ember drops a cloak in about 73% of seeds and Supply in about 31%. Left as is; tuning needs a design decision.

## Honest note on check counts
About 98% of the 10109 CloakSlot checks come from the 3 tables x 400 seeds loot loop; there are roughly 190 distinct behavioural checks. The count is not a measure of coverage breadth.

## Rewritten fixtures (reasons)
- `EmberdelveAffixProfileGate.cs`: expectation `supply 4 / ember 4 / sealed 3` entries became `5 / 5 / 4` because each table gained one appended cloak entry (the original 4/4/3 entries are still asserted by index and rarity right below, plus new checks for the three appended entries). Coverage kept and extended.
- `EmberdelveAttributeSkillGate.cs` `UnequipAll`: loop upper bound `EquipmentSlot.Legs` -> `EquipmentSlot.Back`, so it also takes off a cloak (no assertion weakened; that gate never wears one).
- No other fixture assumed 5 slots (grep for `SlotCount`, `(EquipmentSlot)`, `Count == 5/6` found only those).
- Determinism: adding a weighted entry to a table necessarily changes the weighted draw, so the loot an authored chest seed (101/202/303/404/505) yields differs from before U2B11. The explicit seed block of the profile gate (303/404/505) still passes.

## Open follow-ups / honest limits
- No windowed screenshot review: 720p/1080p containment is asserted from rectangles, not eyeballed. The tooltip panel, rarity colours and the 54 px slot size need a live look.
- Selection state is still `(ItemData, origin cell)`; only the tooltip is instance-keyed (selection already resolves through the grid to the exact stack).
- `ItemTooltipModel.RarityColor` values are placeholders; a cloak has no world/icon art beyond a coloured block.
- Starting kits and enemy drops do not include cloaks; ground pickups still cannot hold an instance (R4).
- `EquipmentSlot.Legs` is still the boots slot.
