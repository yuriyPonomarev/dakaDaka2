# R4+R5: one seeded loot/identity pipeline, per-raid seed, project RNG

## Verified starting point (HEAD c112e97d)
- `EnemyAgent.DropLoot` used `UnityEngine.Random` (chance, pick, scatter) over a flat `ItemData[]`; drops were definition + 1; `LootPickup` held only `ItemData` + amount.
- `LootTable` / `LootRoller` used `System.Random`; every `TryRoll` built a fresh local issuer; the bag minted with its own issuer.
- Chest seed = the authored layout int, so chest loot was identical every raid (F7).

## Design
**RNG** (`Runtime/Core/DeterministicRng.cs`): `ILootRng` (NextUInt64/UInt32, Next(max), Next(min,max), NextDouble) and `DeterministicRng`, SplitMix64 with explicit 64-bit state. Integer paths use unbiased rejection sampling and no floating point (the gate scans the source for that); `NextDouble` = (bits>>11)*2^-53 (exact IEEE). `Fork(streamId)` derives a stream from the ORIGINAL seed (not the current state), so streams never depend on each other's consumption. `RngMix.Combine(a,b) = Fin(Fin(a^G)+b+G)` (non-commutative), `HashString` = FNV-1a 64 over UTF-8. Reference vectors (SplitMix64 seed 0 / 1234567) match the published ones; all other vectors come from an independent Python implementation.

**Seed derivation** (`Runtime/Items/RaidSession.cs`, all via `Combine`):
```
chestSeed(raid, chestId, salt) = C(C(C(raid, H("chest")), H(chestId)), uint(salt))
enemyDropSeed(raid, dropKey)   = C(C(raid, H("enemy-drop")), H(dropKey))
uidStreamSeed(raid)            = C(raid, H("uid"))
LootTable streams              = Fork(1) item/amount shape, Fork(2) affixes
```
Authored chest seeds on the layout are now SALTS. `chestId` = the chest GameObject name (spawner: variant, cell, layout index). Enemy `dropKey` = `enemyId@round(4x),round(4z)` of the spawn point (stable per layout). (raid seed, chest) -> same items, amounts, affixes; different raid seed -> different.

**Raid seed** (`RunContext.ResolveRaidSeed`): 1) `SetNextRaidSeed(ulong)` (explicit, consumed once, so a retry never replays it); 2) editor/development builds only: `-emberdelveRaidSeed N` or env `EMBERDELVE_RAID_SEED`; 3) `DefaultRaidSeed()`: Guid.NewGuid bytes + UTC ticks + per-process counter mixed. The seed and its source are logged (`[Emberdelve][Raid] raid seed 0x... (entropy)`).

**Issuer ownership**: `RunDirector.Awake` builds one `RaidSession` per run (so a result-screen retry = new scene load = new session, new issuer). `RunDirector.Start` points the bag at `Session.Issuer` (`Inventory.SetIssuer`) before the class/starting kit is applied. Chests (`RaidSession.TryRollChest`), enemy drops (`TryRollEnemyDrops`), legacy gear mints and starting kit all use that issuer. A chest whose host has no `IRaidSessionHost` refuses to roll (no private fallback). `ItemIdentityIssuer` now keeps its own issued-UID ledger (`HasIssued`, redraw on collision, mints nothing after 8 repeats) and can be seeded (`CreateSeeded(ILootRng)`).

**UIDs: unique, NOT reproducible by default.** Contents and affix rolls are deterministic from the seed; identities are random 128-bit (ledger-checked) so replaying a seed into one profile cannot duplicate items. `RaidSession.Begin(seed, source, deterministicUids: true)` draws UIDs from the seeded uid stream (tests/replay tooling); two such sessions issue the same UIDs and a profile `ItemUidRegistry` refuses the replay (tested).

**Enemy drops**: `EnemyData.dropTable` (a real `LootTable`; legacy `lootTable/lootRolls/lootDropChance` kept as authored data, no longer rolled). `EnemyAgent` only reports death to an `IEnemyDropHost`; `RunDirector.DropEnemyLoot` rolls the table with the session, scatters pickups with a deterministic stream, spawns gear as instance pickups. `LootTable.nothingWeight` (default 0 = old streams unchanged) encodes a per-roll miss. Builder `ApplyEnemyDropTables` creates `Loot_Enemy_HollowServitor/AshenWarden` (idempotent). **Servitor** (three items w8, max 2 copies each, empty weight 6, 2 rolls) is equivalent to the legacy rule: 1.6 units per kill, 0.533 per item. **Ashen Warden is a balance change**: 3 rolls over Relic w9 (max 1), Coin w8 (max 2), Draught w6 (max 2), Footpad Boots Uncommon w4 (max 1), empty weight 3. 90% is only the first roll's chance; once a capped entry is taken the remaining weight shrinks (the miss chance is relative to the weight still available). Expected units per kill, legacy -> new: Relic 0.90 -> 0.68, Draught 0.90 -> 0.68, Coin 0.90 -> 0.90, Footpad Boots 0 -> 0.39 (items 2.70 -> 2.65). Relics are the sealed-chest unlock currency (`SealedUnlockValue`), so Wardens now give less unlock value; the Uncommon boots are the first enemy gear drop (kept on purpose to exercise the instance path). The LootPipeline gate pins these numbers by simulating 6000 kills (tolerance 0.035). `RunDirector.Awake` coverage check now covers enemy drop tables (items, affixes, `Validate()`).

**Pickups**: `LootPickup.Configure(ItemInstance, host)`; taking it goes through `LootCollection.TryCollectInstance` -> `RunDirector.TryCollectLootInstance` -> `Inventory.TryAddInstance` (catalog-validated). Refusal leaves the pickup and the same instance untouched; success destroys it. Definition pickups keep the counted partial contract. The pickup bob phase now derives from position (no `Random`).

## Rewritten fixtures
- `EmberdelveLootRollerGate`: `FixedRandom` and `new System.Random(seed)` -> `ILootRng` / `DeterministicRng.FromInt(seed)` (roller no longer accepts System.Random). Scripted ticket values and all assertions unchanged.
- `EmberdelveItemCatalogGate`: `System.Random(5)` -> `DeterministicRng.FromInt(5)`; coverage check also covers `dropTable` entries/affixes.
- No other gate needed changes. Chest gates use the live `RunDirector` (now a session host) and assert counts/conservation independent of the raid seed; the smoke `items` test compares table rolls with the same int seed, which remain deterministic (expectations re-derived by the new RNG, not hard-coded). `TryRoll(int ...)` overloads remain as tooling/test convenience (zero-extended seed, throwaway issuer); production code never calls them (scan).
- Re-baseline: because the generator changed, the specific items a given int seed produces differ from before R4; no gate hard-coded such outputs.

## New gate `EmberdelveLootPipelineGate.Run` (play mode, Level01)
RNG known answers (SplitMix64, NextUInt32/Double, Next(int), Next(min,max), Fork), range edges, uniformity, stream independence, no-float integer paths; seed-derivation vectors and domain separation; table known answers (independent Python oracle) incl. `nothingWeight`; same (raid, chest) identical contents incl. affixes (random uids differ, seeded uids replay); 300 raid seeds -> 300/300 distinct ember and sealed contents; 5 real chests derive distinct seeds; real run wiring (bag issuer is the session issuer, legacy mint counted); 1000+ simulated chest/drop items, no UID collision (random and seeded sessions), disjoint in a profile ledger; issuer refuses a repeating source; per-run issuer reset, replay refused by ledger; chest without session refuses; live enemy kill -> instance pickup (Rare boots, 2 affixes) -> bag exact snapshot -> equipment exact; Common/Uncommon/Rare ground pickups preserved; full-bag refusal leaves pickup + same instance, retry delivers; duplicate identity refused; definition pickup partial contract; real ember chest uses the raid issuer; source scan (no UnityEngine/System.Random in Runtime except allowlist `AI/EnemyBrain.cs` (strafe jitter) and `Feedback/TorchFlicker.cs` (visual), allowlist staleness check, explicit scoped file list, no private issuer creation).

## Open follow-ups
- `EnemyBrain` still uses `UnityEngine.Random` for patrol waypoint angle jitter (AI movement, not loot or identity; allowlisted, label corrected); seed it from (raid seed, spawn key) when AI becomes server-authoritative.
- Starting-kit instances: the current classes' kits are carried goods only, so "kit through the issuer" is proven by the bag's issuer identity and the legacy mint, not by a gear starting item.
- Run seed is not yet handed from a lobby/server (only `SetNextRaidSeed`); a server must keep the seed secret since contents are derivable from it.
- `ILootHost/ICountedLootHost/IInstanceLootHost/IEnemyDropHost/IRaidSessionHost` are still separate interfaces (merge pending).
- Enemy drop keys are `enemyId@cell` plus a `#n` allocation-order suffix for co-located enemies (invariant culture, reset per run in `RunDirector.Awake`); explicit spawn ids in the layout and a per-spawn kill counter (respawns) are still open.
- `EnemyData` legacy `lootTable/lootRolls/lootDropChance` fields can be removed once the smoke test stops reading `lootTable[0]`.

- Review follow-ups not done: S7 (the legacy `lootTable` field comment), S8: the coverage message still prints `Validate()` problems under the "not in the item catalog" heading; enemy drops use `config.itemCatalog` while chests use the bag's catalog (pick one, pass the run catalog explicitly); the interface merge; `HashString` constants and per-roll allocations; the gate mutates the shared `EnemyData.dropTable` for one frame (use a clone); `ItemIdentityIssuer` is not thread-safe; the bag is still a mint entry point for legacy gear adds (H2 "move minting out of the bag" still open).
