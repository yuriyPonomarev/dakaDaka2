## Changes
1. Combo pips.
   - `CombatContracts.cs`: new read-only `IComboStateSource.TryGetComboState(combatId, out step, out total, out windowRemaining)`; `LocalCombatAuthority` implements it (`Swings.cs`). False for unknown ids and for any held weapon without a chain (ranged, shield, single pattern). `step` = chain steps started in the live chain (0 = none, the finisher in progress reads `total`), `windowRemaining` = authority-clock seconds until the live chain resets (0 when none). Same liveness rule as `TryGetExpectedComboStep`; it mutates nothing. `ICombatAuthority` itself is unchanged (no fake to update).
   - `HudController` (UI asmdef, reads Runtime only): group `HudRoot/Crosshair/ComboPips` with `ComboPip0..4` (10 px squares, 16 px pitch, 40 px under the crosshair) and a 2 px `ComboWindow` bar. `Update` polls the held weapon (`rig.ActiveWeapon`) and the authority, then `ApplyComboPips(step, total, windowFraction)` (internal, writes UI only when the quantised state changed). Hidden for total < 2 (no chain, ranged, one-step). Lit pips amber while a continuation is possible, dull when the window is closed or the chain is complete; the bar shrinks with the window (fraction = remaining / `weapon.comboWindow`, 1/32 steps).
2. Wall-stop feedback.
   - `MeleeSwingStatus` gets trailing optional `WallPoint`, `WallNormal`, `HasWallPoint`; the authority records them at the stop sample (hand-line hit point, buried hand = the hand, or the blade ray hit). The `Linecast` calls are the same queries as before (one now uses the `out RaycastHit` overload); wall decisions are untouched.
   - `MeleeCombat.WallStopped` (new event, raised once at the moment the client starts its recoil, guarded by `_recoilStarted`). `FeedbackDirector` forwards the local player's event to the new `WallStopFeedback` (pooled spark, 6 slots x 4 shards, shared material, no per-frame allocation) and the new `CameraKick`.
   - `CameraKick`: pitch (max 3 deg, authored 1.1 deg) and back-offset (max 8 cm, authored 3 cm) impulse, exponential decay 14/s, snaps to exactly zero. It is applied to the aim transform ONLY between `RenderPipelineManager.beginCameraRendering` and `endCameraRendering` for its own camera, then the exact saved local pose is restored. Everything that reads the transform outside rendering (PlayerLook, `PlayerRig.TryGetAimPose`, movement, the weapon rig, the authority) never sees it; PlayerLook yaw/pitch fields are never written.
   - `WeaponVisualRig.ClipBladeLength(base, dir, length, mask)` clips the drawn bar (`Sweep_Edge`) and the ribbon at level geometry using the authority's own `SwingBlockerMask` (props and triggers do not clip; a buried hand draws nothing). The sword model itself is not clipped. Raycast + CheckSphere, no allocation.
3. Hit-location marker. `HitFeedback` has trailing optional `Location`, set from `damage.Location` at all four creation sites (melee swing, weapon attack, skill, projectile). `HudController.OnDamageDealt` (already filtered by `PlayerView.Shows`, i.e. hits the local player dealt) styles the marker: head (or headshot flag) gold, 1.45x, held 0.38 s; body/unknown = the original; arms/hands 0.85x alpha 0.8; legs/feet 0.75x alpha 0.7.

## Risks
- Not compiled. Likeliest compile points: `HudController.HitMarkerStyle` internal nested struct used by the Editor gate (UI assembly has `InternalsVisibleTo("Emberdelve.Editor")`), tuple `foreach` in the gate, named trailing args on `MeleeSwingStatus`, `RenderPipelineManager.beginCameraRendering` (URP only; a built-in-pipeline camera would show no kick).
- Kick ordering: applying inside begin/endCameraRendering assumes URP reads the camera transform after `beginCameraRendering` (true for URP 17). If a build shows no kick, the kick math is still gate-verified; only the hook point would move. The weapon rig is posed in LateUpdate from the un-kicked camera, so the held weapon does not jolt with the view (accepted, slight parallax).
- The combo-pip poll (`UpdateComboPips`: director -> rig weapon -> authority) is not driven in the gate (service registration with the scene's authority makes it unreliable there); its two halves (authority state, `ApplyComboPips`) are. Needs the live review.
- Blade clip runs one Raycast per frame while the active phase draws; the authority samples on its own tick, so the visual may touch the wall a frame before the stop is reported (expected, <= 1 tick).
- Blocked hits use the same location variant (no separate blocked look). Remote/other players' hits never reach the marker (PlayerView filter).
- Spark and kick are not audio; U5 owns the wall-hit sound.
