- `RefreshStats` scratch still starts empty, then per worn slot adds `Definition.statModifiers` once AND that very instance's own immutable `AffixRecord`s once (new private `AddRolledNumericAffixes` + `TryNumericStatTarget`), then the same single `SetSource(CharacterStatStack.EquipmentSourceKey, …)` + `PlayerRig.RefreshEquipmentStats()` as before — one source, one pass.
- Exact mapping, all `SkillModifierMode.Flat` and never a multiplier: `max_health`→`SkillStat.MaxHealth`, `max_mana`→`SkillStat.MaxMana`, `move_speed`→`SkillStat.MoveSpeed` (metres/second), `mana_regen`→`SkillStat.ManaRegen` (per second). Fixed authored and rolled entries both enter that one source, so they ADD; nothing replaces an authored value. A non-finite record value is skipped rather than applied (a validated instance cannot hold one).
- Order/authority unchanged and re-read before editing: `PlayerRig.ResolveVitalLimits` applies the stack on top of the CON/INT/WIS-derived bases — `MaxHealth`/`MaxMana` keep their authored `Mathf.Max(1, Mathf.RoundToInt(...))` integer path (documented, not changed), `ManaRegen` keeps `Mathf.Max(0f, …)`; walk stays `clamp(authored * max(0.5, 1+0.025*DEXmod) * stackMultiplier + stackFlat, 2, 8)` in `AttributeRules.MoveSpeed` via `PlayerMovement.ResolveWalkSpeed`, so sprint/crouch (their own `SprintSpeed`/`CrouchSpeed` terms) and guard/aim/status multipliers cannot be moved by a walk-only m/s affix.
- The six attribute keys are deliberately NOT added to this source (U2B5 already applies them through `StatsComponent.RebuildFromInstances`, so adding them here would double count). `armor`, `melee_damage`, `projectile_damage` are explicitly DEFERRED to the next combat-affix task — no mapping to `BlockReduction`/`MeleeDamage`/`RangedDamage` here, and none was added.
- No healing/refill/clock reset: gear paths still take only `SetMax` (clamp-down) plus `SetRegen` with the run's existing delay — no `Configure`/`InitializeVitals`/refill on any refresh. UID/rarity/rolls untouched (records are read only, no reroll/mint/asset write); the source is replaced wholesale each pass, so unequip, a swap between two rolls of the same base and repeated refresh are exact and non-accumulating.
