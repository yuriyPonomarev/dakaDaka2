# Player sword timing data: code-authored values are canonical (24 Nov 2026)

## Decision

The committed player weapon/pattern assets had drifted from what `EmberdelveAssetLibrary.BuildAll()` authors. The user first chose to keep the committed values, then (after mirror evidence below) chose the code-authored values. Final decision: **the values authored by `EmberdelveAssetLibrary` are canonical**; the Data assets are regenerated from it.

## Evidence that led to the change

- On committed (HEAD) data, SweptMelee failed 725/5 (run 20261119-012844-536, before any enemy work) and CombatFlow 524/34.
- On data regenerated by `BuildAll` (22 Nov working tree), SweptMelee 729/0, CombatFlow 588/0 and ActionSpeed 196/0 all passed (runs 20261122-014545-766, 20261122-022845-642).
- An intermediate attempt to make the committed values canonical (library code rewritten to author them, SweptMelee/CombatFlow gates rewritten to derive floors from data) made SweptMelee pass (732/0) but left CombatFlow 586/11 and ActionSpeed 196/46 failing (run 20261124-155312-204). That attempt was discarded; its patch is not committed.

Conclusion: the regenerated data had been tuned and tested but never committed.

## What changed (Data only, regenerated by BuildAll; no code change)

- Combo step scales: `Weapon_AshenShortSword`, `Weapon_ArmingSword`, `Weapon_TwoHandedSword` (step recovery 0.5 -> 1, step windup 0.6 -> 0.85/0.9/1), `Weapon_EmberRapier` (0.25/0.35 -> 0.9/1).
- `Pattern_SwordSlashLR`/`RL`: windup 0.28 -> 0.24, recovery 0.34 -> 0.30 (now mirror the weapon's legacy timing fields again).
- Serialized defaults for fields added after the assets' last save (`rangedGuardShape`, `impactGuard*`, `parryBladeRegion`, `reloadWhileHeld`, item footprint/stack on `Item_ArrowBundle`); Unity already loaded these defaults, so runtime behaviour for them is unchanged.
- `EmberdelveItemCatalog`: two entries swap order (library order).
- `Pattern_ClawOverhead`: gains the shared swing trail material the library assigns.

Other Data assets touched by the rebuild differ only in line endings and are not committed. License/manifest files and two PolyHaven materials rewritten as a side effect were restored to HEAD.
