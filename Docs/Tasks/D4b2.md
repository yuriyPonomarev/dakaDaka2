## Behavior and exact scope

- `ActionSpeedRules.ReloadDuration(authoredSeconds,actionFactor)` is the shared engine-free rule: `max(.1, authored reload seconds / sanitized rate)`. There is no melee .8 cooldown grace in reload math. Invalid/NaN/infinite/nonpositive factor uses neutral1. Overflow/nonfinite division safely falls back to finite neutral authored duration; invalid authored metadata has a safe .1s base. Finite positive rates remain tunable, with a .1s accepted-duration floor.
- Sender-bound `LocalCombatAuthority.TryStartReload` still authorizes the sender and resolves the live registered entity/kit first. It reads optional IActionSpeedSource from that registered entity (otherwise1), calculates accepted duration, and passes the value to the authority-owned kit state. No factor or accepted duration enters any command or KitSeed/KitAmmoSeed from client intent.
- `CombatKitState` retains the accepted duration unchanged while its remaining timer ticks. `KitView.ReloadDuration` explicitly carries that value. Existing `KitView.ReloadTime` remains the authored pool metadata. Class/weapon cancellation and completion clear accepted duration; equipment Revision continues its existing clamp-only mana behavior and does not retime/cancel reload.
- `RangedCombat.ReloadProgress` divides remaining by captured accepted duration. Authority views copy it explicitly. The unbound legacy StartReload path calls exactly the same shared timing helper once, then retains its own capture through regear. Weapon initialization/finish clears local timing state. Progress remains0 when idle.
- Existing weapon-change cancellation, sender/ammo ownership, one transfer at completion, reserve limits and clamp-only revisions remain. Six names, scores, save keys, mana, melee timing, draw/charge and skills are unchanged. The profile action tooltip now states swept melee+reload while excluding draw/skills.
- This is still the local/offline combat authority and its future server read seam; no network-authority acceptance is claimed.
