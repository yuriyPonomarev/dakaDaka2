- Factories: `ItemInstance.TryCreateNew(definition,quantity,rarity,IReadOnlyList<AffixRecord>,authority,out instance,out reason)` mints exactly one UID only after everything else validates (a refusal mints nothing); `TryCreateWithUid(Guid,…)` uses the supplied UID as-is and refuses `Guid.Empty`; `TryRestore(snapshot,authority,out instance,out reason)`; `TryValidateSnapshot(snapshot,authority,out reason)`; `instance.TryCopy(authority,out copy,out reason)` and `instance.TryWithQuantity(quantity,out next,out reason)` both carry the same UID; `instance.ToSnapshot()` returns a fresh deep DTO copy.
- Immutability: private constructor only (no default instance, no silent UID), all fields readonly, input affix list deep-copied, the affix array is private and reachable only through a nested view implementing nothing but `IReadOnlyList` (a cast to `IList`/array throws `InvalidCastException`), snapshot output is a new object graph, `AffixRecord` is a readonly struct; nothing clamps, trims, normalizes, rerolls or regenerates, and accepted values are stored/exported exactly.
- Validation is atomic (false + one reason + null output): null authority or definition; malformed item id; quantity ≠1 for worn/held gear or outside 1..`ItemData.StackLimitForFootprint` for carried items; unknown rarity (enum cast or raw DTO int, never clamped); affix count ≠ the 0/1/2 the rarity requires; trusted category from the resolver (`None` only legal with 0 affixes; rolled gear needs one known category and an equippable definition); unknown/malformed affix id; id/key mismatch against the catalog definition; duplicate affix id or duplicate stat key; nonfinite/out-of-range/off-step value and disallowed category via `AffixDefinition.TryValidateRolledValue(value,category)`; snapshot-side malformed UID (strict 32-char lowercase canonical `N`, all-zero rejected), unknown item id, null affix entry, non-canonical key text.
- Category mapping is the explicit trusted delegate for this slice: Weapon→Weapon, OffHand/Head/Chest→Armor, Legs→Boots, None→None; cloak/back has no `EquipmentSlot` value yet, so a supplied resolver is the documented bridge and no slot was added or renamed.
- Deliberately absent (documented in code): RNG/weighted rolling (U2B3), stack split/merge/transfer and inventory ownership, effective-bonus application, persistence/UI/network. Immutable quantity updates preserve the UID; a genuine split would need a new UID from the issuer, and contested-UID ownership stays server work (U3B/U4A).
