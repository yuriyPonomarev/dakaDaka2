# R3: one runtime item catalog; the bag stops minting gear for arbitrary ItemData (F5)

## Verified starting point (HEAD 63f8a4d1)
- `Inventory.TryAdd/TryAddAt` minted a Common UID for any equippable `ItemData`, validating against `LocalCatalogFor(definition)`, a one-entry catalog built from that same definition, so the check could not fail.
- `LootTable.TryRoll` built a per-table authority from its own entries (`TryBuildAuthority`), the same self-reference.
- No project-wide catalog existed. `ItemInstance.TryRestore(snapshot, authority)` was correct but there was no process authority to hand it. `ItemSnapshot` is already a dumb DTO (no category, no definition ref); it needed no change.

## Design
**`Runtime/Items/ItemCatalog.cs`** (ScriptableObject, `Assets/Emberdelve/Data/EmberdelveItemCatalog.asset`, referenced by `GameConfig.itemCatalog`):
- Lists every `ItemData` asset (10: weapon, shield, chest, boots, 2 cloaks, coin, potion, arrows, relic) and the 13 affix assets.
- `Validate(items, affixes, requireAffixesForGear, out authority, out reason)`: null refs, invalid ids (`ItemIdentityRules.IsStableItemId`), duplicate ids (two objects, or one object twice), invalid affix catalog, unresolved gear category, and (production rule) equippable gear with no affix catalog are all errors.
- `TryGetAuthority/Authority`: the ONE `ItemInstanceAuthority`, built once and cached (failures cached too). `Contains(def)` is reference equality with the catalog's own object. `TryResolveItem/TryResolveAffix` by id.
- `CanMint` / `TryMintCommon(issuer, def)`: the only door that mints a Common gear identity; refuses clones, ad-hoc ids, carried items, null.
- `TryDeriveAuthority(items, affixes)`: a rolling view for one container; every member must be the catalog's own object (a table may restrict what it rolls, never widen what exists).
- `TryRestore(snapshot)` / `TryRestoreAll(list)`: resolve by id through the catalog; the batch is atomic (unknown id, tampered record or repeated UID produces nothing).
- Test seam: `CreateForTest(items, affixes)` makes an in-memory catalog (HideAndDontSave, `IsTestCatalog`); `RegisterForTest(def)` validates the candidate list first (duplicate/invalid id rejected, nothing changes) and **refuses on any non-test (asset) catalog**. Shared definitions are never mutated.
- `EditorSetContents` (UNITY_EDITOR only) writes only when the lists differ, so the builder is idempotent.

**Builder** (`EmberdelveAssetLibrary.BuildItemCatalog`, after `BuildAffixCatalog`, before loot tables/config): `LoadOrCreate<ItemCatalog>`, items = `t:ItemData` under the data folder sorted by path (ordinal), affixes = builder-owned `Affixes`; validates and logs errors. `BuildConfig` assigns `Config.itemCatalog`. No scene change (scenes reference the GameConfig asset).

**Runtime wiring**
- `Inventory`: `LocalCatalog`, `LocalCatalogFor`, `_lastCatalogFailure` deleted. New `Catalog`, `SetCatalog`, private `CanMintGear` pre-check. `TryAdd` and `TryAddAt` of a gear definition that is not a catalog entry (or on a bag with no catalog) is refused with a reason before any state changes: no UID minted, `accepted == 0`, no stack, counters untouched. `TryAddInstance(At)` also refuses an instance whose definition is not a catalog entry when a catalog is set. New `TryAddSnapshot(ItemSnapshot)`: resolve by id via the catalog, then `TryAddInstance` (exact UID/rolls, no mint, atomic).
- `ClassLoadout.Apply`: `rig.Inventory.SetCatalog(config.itemCatalog)` before the grid and starting kit (a config with no catalog keeps a catalog the bag already has; none at all logs an error). `RunDirector.Awake` validates the config's catalog once and logs an error if it is missing or invalid.
- `LootTable`: legacy `TryRoll(seed,out)`, `TryRoll(seed,issuer,out)` and `Roll(seed,output)` removed. New `TryRoll(seed, output, ItemCatalog, [issuer], out)` and `Roll(seed, output, catalog)`. `TryBuildAuthority` replaced by `TryDeriveAuthority(catalog)`: gear entries and the table's affix subset must be catalog members, otherwise the whole roll is refused (output empty, nothing minted). Carried-only tables still need no catalog. Item/amount stream, affix stream and determinism are unchanged (ember/sealed tables use the same 13 affixes in the same order).
- `ChestInteractable.Open`: rolls against `host.Inventory.Catalog`.
- Production code no longer calls `ItemInstanceAuthority.TryCreate` anywhere except `ItemCatalog` (asserted by the gate with a source scan).

## New gate: `Emberdelve.EditorTools.EmberdelveItemCatalogGate.Run` (120 checks after review fixes)
- BuildDataOnly twice: stable GUIDs, no file added or removed, all data/meta byte-identical, and identical to the tree the gate started on.
- Coverage: catalog == every ItemData asset in `Data` (no orphans, no null/foreign/stale entries), every id resolves to its own asset, all kinds and slots covered, 13/13 affixes, GameConfig references the catalog. Every loot-table entry/affix, class starting item and enemy drop in the data is a catalog entry.
- Build errors: null item, null lists, empty list, invalid ids (uppercase, empty, space, padded, too long), duplicate id (two objects / same object twice), gear without affix catalog (carried-only is fine), duplicate affix stat key; a broken catalog serves no lookup.
- Minting: refused for a clone of a real item, a fresh-id definition, a carried item, a null definition, a null issuer (issuer count stays 0); succeeds for a catalog entry.
- Bag: with no catalog it refuses gear (state string identical before/after); refuses clone x1, clone x3, ad-hoc, and `TryAddAt` of both (state unchanged); a starting kit with non-catalog gear gives only the catalog entries; an instance of a non-catalog definition is refused by a catalogued bag.
- Test seam: register ok, idempotent, duplicate id rejected, invalid id rejected, null rejected, **asset catalog refuses RegisterForTest**.
- Loot tables with non-catalog gear / clone / foreign affix / null catalog refuse and mint nothing; a carried table still rolls with no catalog; the real ember table rolls 60 seeds deterministically.
- Snapshots: round trip of a Rare shield (exact uid/def/rolls) through the catalog and the bag; duplicate uid refused with identical bag state; unknown item id refused (catalog and bag, bag state unchanged); a batch with one unknown id restores nothing; a batch with a repeated uid restores nothing; a valid batch restores; case-folded id, tampered rarity, malformed uid and null snapshot refused; a no-catalog bag cannot restore.
- Source scan: no production `ItemInstanceAuthority.TryCreate` outside `ItemCatalog.cs`, no `LocalCatalogFor`.

## What still bypasses seeded loot or the catalog (documented only, belongs to R4)
- `EnemyAgent` drops (`EnemyAgent.cs:174-180`) use `UnityEngine.Random.value`, `Random.Range` over `EnemyData.lootTable` and `Random.insideUnitCircle`; `LootPickup` also uses `Random.value` for its bob phase. Nothing is seeded or tied to a raid seed.
- Enemy drops and ground pickups are `ItemData` + amount (`RunDirector.SpawnLoot` -> `LootPickup` -> `CollectLootCounted` -> `Inventory.TryAdd`). A pickup holds no `ItemInstance`: a gear definition gets a fresh Common UID at pickup time (catalog entries only now). Carried goods stay definition-only.
- `LootTable.TryRoll` and `ChestInteractable` still use a fresh `ItemIdentityIssuer.CreateLocalTrusted()` per roll; there is no per-run issuer or run-owned authority object.

## Review fixes (Docs/Reviews/R3.md, ACCEPT-WITH-FOLLOWUPS)
- **M1** `ItemCatalog.CreateForTest` and both `RegisterForTest` overloads are now `internal` (editor assembly sees them through the existing `InternalsVisibleTo("Assembly-CSharp-Editor")`). There is no asmdef split, so the gate's production source scan now also fails if any `Runtime` file other than `ItemCatalog.cs` contains `CreateForTest(` or `RegisterForTest(`.
- **M2** `Inventory.TryAddInstance(At)` now re-validates the instance against the catalog authority (`ItemInstance.TryValidateSnapshot(instance.ToSnapshot(), catalog.Authority)`): a hand-built instance of a real definition carrying a foreign affix id, or a real affix id with a forged stat key, is refused with the bag unchanged. New gate checks cover both forgeries, `TryAddInstanceAt` for a forgery and for a non-catalog definition. Fixture fallout: FlatDamageAffix, NumericAffix and RolledAttributes roll with their own ad-hoc affixes, so each bag now carries an explicit test catalog (real boots + exactly those affixes); GearInstance/ArmorAffix/ChestInstance/CloakSlot/items already did.
- **H3** A bag with no catalog now refuses every ready-made instance (new gate check, plus the same legitimate instance is admitted by the catalogued bag). The `items` smoke loads the production catalog by asset path instead of reading it off the bag, so a catalog-less bag cannot crash it.
- **H1** `RunDirector.Awake` additionally checks coverage once: every item in the configured chest tables (and their affixes), floor loot, enemy drops and class starting kits must be a catalog entry; one aggregated `LogError` names what is missing.
- **Flake (test only, `EmberdelveRuntimeSmokeTest`)**: root cause was an uncontrolled environment, not the runtime. Fixed: (1) every other enemy is parked (`SetActive(false)`) for the whole `DefenseFlow` (which contains `OffAxisWindupFlow`) and restored afterwards; (2) an enemy spot is chosen where all three strafe spots are walkable, collider-free (capsule check lifted 0.12 m off the floor) and in line of sight, else the check fails with the reason per candidate; (3) `PlayerMovement` is frozen while placing the player (collider kept so the enemy still has a target); (4) assertions are per enemy (`LastSequenceFor(enemy.CombatId)` advances, exactly one damage event with that `SourceCombatId`, `!LastAttackWhiffed` inside the wedge; outside: sequence unchanged, no damage, whiff recorded); (5) on failure a DIAGNOSTIC line logs brain state, distance, angle to the warned direction, line of sight, reject reason, strafe spot and nearby enemies. Assertion intent unchanged (inside => hit lands, outside => whiff). The combat count is 230 (+3: arena check and two per-enemy checks). Five consecutive combat runs: `Logs/r3flake_exit.txt` (all PASS 230/0), plus the combat run inside the final sweep.

## Open follow-ups (from the review, not done here)
- **H2** The bag is still a mint point (own issuer per bag, starting kit minted by the bag; each loot roll derives a fresh authority and local issuer). Moving minting to the run/server with one issuer and authority per run is R4/U3; R3 only stops minting for non-catalog definitions.
- **R9** instance admission now fails closed on a catalog-less bag; container snapshot restore through `TryRestoreAll` / `TryAddSnapshot` is still to come.
- **M3** the chest takes the run catalog from `host.Inventory.Catalog`; pass it explicitly (ILootHost or `ChestSpawner.Ensure(layout, config, ...)`).
- **M4** `ClassLoadout.Apply` keeps a bag's existing catalog when the config has none (test convenience); prefer always assigning `config.itemCatalog` and logging when null.
- **L1** widen the gate further (a chest with a non-catalog gear entry shows "invalid" and stays unrolled); the substring source scan is only a tripwire (asmdef split would make it structural); the gate runs BuildDataOnly so it writes to the data tree (same F8 concern as smoke calling BuildAll).
- **L2** `EmberdelveTestCatalog.Release` destroys the test catalog but leaves the bag pointing at it (harmless: only called at teardown); restore the production catalog there. `ManagerInventoryGeometryProbe` is outside the regression list and not run.
- **L3** `ItemCatalog.Items/Affixes` expose the live serialized arrays as `IReadOnlyList` (a cast could mutate them): return copies. The cached authority is not invalidated by an inspector edit of an `itemId` during Play (editor-only). Adding the first gear item to a fresh project needs an affix catalog too (intended production rule).
- An asset-postprocessor/validation menu that flags ItemData assets not in the catalog (H1 optional).
