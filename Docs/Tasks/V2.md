# V2: dark retro dark fantasy (visual-only slice)

Status: written, NOT compiled and NOT run (no Unity in the authoring environment). Every API call was checked by hand against Unity 6000.2 / URP 17.2 and nearby project code; `EmberdelveRetroVisualGate.Run` plus the graphical review must confirm it.
Base: commit 368f19d (live code + uncommitted U3B2 network work, untouched: `Assets/Emberdelve/Net/**` and `NetRules/**` are not modified).

## What and why
The V1 look (torch-lit darkness, ambientCG stone, ACES/bloom/vignette/grain) stays. V2 adds a late-90s rendering feel and replaces the placeholder cubes with real CC0 models.
1. **Vendor import** (`EmberdelveVendorImport`, menu `Emberdelve/Visual/Import KayKit Assets`, also called by `EmberdelveMaterials.BuildAll`, `EmberdelveBootstrapMenu.BuildEverything`): copies the KayKit packs from `<project>/Logs/v2_assets/{skeletons,dungeon}` to `Assets/Emberdelve/Art/ThirdParty/KayKit/{Skeletons,Dungeon}/` (same relative layout) only when a file is missing or differs (length, then timestamp, then SHA-256; `force` always hashes), copies both `LICENSE.txt`, creates the project materials `KayKit_Skeleton / KayKit_SkeletonGlow / KayKit_Dungeon` (URP Lit, atlas, no specular/reflections) and writes `KayKit/manifest.json`. Once per editor session unless forced; a missing source folder only logs a warning (the level then keeps the V1 look) and the gate fails on it.
2. **Import settings** (`EmberdelveKayKitImport`, AssetPostprocessor, scoped to the KayKit folder): characters Generic rig, avatar from model, animations on, bones kept (no GameObject optimisation, the weapon needs `handslot.r`), loop flag on every take containing "idle" and those starting with "Walking"/"Running"; props/weapons no rig/animation; FBX materials `skeleton`, `Glow`, `texture` remapped to the project materials; no cameras/lights/colliders/blend shapes. The take list only exists after a first import, so the vendor import re-applies the loop flags and does one `SaveAndReimport` per character (first run only).
3. **Enemies** (`EmberdelveEnemyVisualFactory`): per variant (Minion, Rogue, Warrior, Mage) an `AnimatorController` generated from the clips in the character FBX (states Idle, Walk, Run, Attack, Hit, Death; params Speed float, AttackSpeed float, Attack/Hit trigger, Dead bool) and `Assets/Emberdelve/Prefabs/Visual/EnemyVisual_<Variant>.prefab` (unpacked model fitted to 1.9 m, weapon on `handslot.r`, Warrior shield on `handslot.l`, `EnemyVisualDriver`). The level builder attaches the prefab as child `Visual` of each enemy. Mapping: elite (Ashen Warden) = Warrior with axe + small shield, scaled 1.25 like its hit volumes; Hollow Servitor = Minion (even spawn index) or Rogue (odd), both with the blade; Mage is built but unused (no caster enemy exists; no ranged enemy, so the crossbow is imported but unused).
   Clips: Minion Walking_A/Running_A/1H_Melee_Attack_Chop/Death_A, Rogue Walking_B/Running_B/…Stab/Death_B, Warrior Walking_B/Running_A/…Slice_Diagonal/Death_A, Mage Spellcast_Shoot/Death_B; all Idle + Hit_A. A missing take falls back to the first clip containing a keyword and logs.
   `EnemyVisualDriver` (Runtime/AI, presentation only) reads `EnemyAgent` (IsDead, IsWindingUp, SwingsBegun, Data, Health), and subscribes to `HealthComponent.Damaged` for the flinch. Speed = measured ground speed (the agent moves the transform, not the clip), Attack triggered at the start of the brain windup (the telegraph) with `AttackSpeed` = clip length / (windup + 0.5 s), Hit skipped while winding up or just after an attack, Dead bool on death. It never writes gameplay state (the gate scans its source for damage/status/stun/physics/transform writes). `applyRootMotion` is forced off.
   **Primitive cubes**: Body and Head stay with their BoxColliders, layer, serialized refs (`bodyTransform`, `headCollider`) and materials; only their `Renderer.enabled` is set to false. Reason: the combat code uses those colliders (ranged rays, movement blockers) and `EmberdelveRuntimeSmokeTest` reads the Body renderer's `sharedMaterial` (a disabled renderer keeps it, so that check passes unchanged). The agent's cube lift during the windup and the cube tip-over on death are therefore invisible; the clips replace them. `HitVolumeLayout.EnsureHumanoid` still builds the same volumes at runtime (the visual contains no `HitVolume`).
4. **Props**: chests keep the spawner's cube body + lid (colliders, lid animation, layers, naming, `ChestInteractable` wiring) and get a model as a sibling `<chest>_Visual` (new `ChestVisualSet` asset in `Resources/Emberdelve`, written by `EmberdelvePropFactory.EnsureChestVisualSet`; `ChestSpawner.Build` calls `ChestVisualSet.Attach`, two lines + a facing helper, no random). The cube renderers are disabled. Model lid: the part named `*lid*` is re-parented under a hinge pivot at its rear-bottom edge and `ChestVisualDriver` swings it (same 150 deg/s and sign as the cube lid) when `chest.Opened`. Tiers: Supply = `chest`, Ember = `chest_gold` (warm tint), Sealed = `chest_gold` (cold violet tint). `trunk_medium_A` has no lid and is used as a decorative prop only. Model is fitted to the blockout width and stands on the floor; yaw 0, or 180 when the back is to a +Z wall (the collider box stays axis aligned).
   Torches: `Sconce` (same name/frame) now holds the `torch_mounted` model (`Torch_Model`, 0.62 m, back on the wall plane, no colliders, no shadows) instead of the procedural parts when the model is imported; V1 procedural sconce is the fallback. Flame particles and light unchanged in structure.
   Scatter (`EmberdelvePropFactory.BuildProps`, root `Props`): per room, deterministic (integer hash of cell and room index; no `Random`), cells that touch a wall, are in the room, have no walkable neighbour (8-neighbourhood) outside the room (doorway clearance), are not in the reserved set (start, spawns, extraction r2, loot, enemies r1, chests r1), no two props in adjacent cells, <= 5 per room, 42 % density. Theme per room name (barrels/crates/banners in the Entry Hall, shelves/candles/table in the Library, pillars in the Central Hall, …). Placement by renderer bounds: front towards the room, back 3 cm from the wall face, tall things capped at 1.5 m depth (scaled down to >= 0.6), banners/key ring hang at 0.9/1.5 m. **No colliders on any prop** (they cannot affect nav, LOS, projectiles or movement; the player walks through them like through sconces). Static flag BatchingStatic only.
5. **Retro look** (`EmberdelveRetroSetup`, shader `Art/Shaders/Retro_Fullscreen.shader`, material `Art/Materials/Retro_Fullscreen.mat`): URP's built-in `FullScreenPassRendererFeature` ("Emberdelve Retro Pass", injection AfterRenderingPostProcessing, fetch colour) added to every renderer of PC_High/PC_Low through the same SerializedObject bookkeeping as the renderer inspector (`m_RendererFeatures` + `m_RendererFeatureMap`). Called from `EmberdelveVisualSetup.ApplyRenderSettings`, so both builders apply it. Shader: pixelation (`_PixelSize`, default 2 screen px), quantisation (`_ColorLevels` 32 = 5 bit, done in gamma space), 4x4 Bayer ordered dither (`_DitherStrength` 1), `_Strength` blend (0 = off). **Toggle**: menu `Emberdelve/Visual/Retro Pass/{Apply, Switch ON, Switch OFF}` or `EmberdelveRetroSetup.SetEnabled(bool)` (feature active flag; works in Play mode); `BuildEverything`/`Apply` switch it back on. Textures: ambientCG sets Point, aniso 1, max 512, mipmaps kept (distant stone would shimmer otherwise); KayKit atlases Point, 256, no mips, uncompressed, clamped; normal maps stay `NormalMap` type (Point filtered too, blocky relief; material `_BumpScale` 1.0 -> 0.8). Flame sprite untouched. Volume: bloom 0.5/1.0/0.6 -> 0.32/1.1/0.5 (intensity/threshold/scatter), vignette 0.35/0.4 -> 0.5/0.45, grain kept (0.2). Flame: start size 0.16-0.29 -> 0.09-0.17, lifetime 0.45-0.8 -> 0.35-0.6, colour yellow-white -> yellow-orange -> orange (V1 ended in dark red which turned pink under ACES + bloom), alpha 0.6, material HDR colour 3.12/1.43/0.455 -> 1.8/1.15/0.5, still additive soft sprite, 55/s, max 40.

## Pre-V2 reference used by the retro gate for enemies
Per enemy, s = 1.25 if elite else 1: exactly two colliders, both non-trigger `BoxCollider` on the enemy layer: `Body` at root + (0, 0.95 s, 0) with world size (0.78, 1.45, 0.58) s, `Head` at (0, 1.85 s, 0) with world size 0.44 s; `bodyTransform`/`headCollider` serialized refs point at them; nothing under `Visual` collides or is a `HitVolume`. Chests: body scale = `ChestSpawner.SizeFor(variant)`, interact layer, body + lid colliders non-null, `BodySize` unchanged.

## Known risks (all untested)
- **Model facing**: the torch, chests, props and enemies assume the FBX front is +Z (usual Blender -> Unity import). If a model comes out backwards: chest set `frontSign` (-1) in `ChestVisualSet`, `Visual` yaw 180 in the enemy prefab, torch model rotation in `EmberdelveTorchFactory.TryBuildKayKitSconce`. The review script exists to catch this.
- **Weapon grip**: weapons are attached to `handslot.r` at identity (the KayKit slot is authored for it); if the bone is named differently the lookup falls back to any non-IK "hand" bone, else the model root with a warning.
- **Compile-level uncertainty**: `FullScreenPassRendererFeature` public fields (`passMaterial`, `passIndex`, `injectionPoint`, `fetchColorBuffer`, `requirements`, `bindDepthStencilAttachment`); `ScriptableRendererData.m_RendererFeatures`/`m_RendererFeatureMap` serialized names; `ModelImporter.optimizeGameObjects`, `GetExternalObjectMap`; `AnimatorState.speedParameter(Active)`. Shader: `sampler_PointClamp` comes from URP's Blit.hlsl; if the shader fails to compile (gate check "compiles without errors"; `-nographics` may hide this, so look at the Console in the graphical run), switch it to `sampler_LinearClamp` with exact texel coordinates.
- **Pass order**: the pass is expected between URP's post-processing and the final blit (dither/FXAA there add negligible noise after quantisation). If the colours look un-tonemapped or double-graded, change `injectionPoint`.
- **First import is slow** (4 x 22 MB FBX imported, then re-imported once for loop flags). `Logs/v2_assets` must stay until the project copy exists; afterwards it is only read for hash comparison (skipped when length and timestamp match).
- **Props are walk-through** by design (no colliders). Wall hangings use guessed heights (banners 0.9 m, key ring 1.5 m bottom); `table_long_broken` / `rubble_large` may be wide and are scaled down to 1.5 m depth.
- **Skinned meshes** (6 skeletons) cast and receive torch shadows; `CullUpdateTransforms` stops animating offscreen skeletons (weapon bones too).
- **Death**: `EnemyAgent` still destroys the object after 6 s; the Death clip is longer or shorter than that depending on the take (visual only).
- **Lobby** gets the retro pass, the new torch model and flame but no props / enemy models; the player's first-person viewmodel (weapons, hand torch) is unchanged.
- **Gate heuristics**: enemy visual height must be 1.3-2.6 m x scale (from skinned bounds; a T-pose model with extended arms does not change height). Bounds-based prop/hinge/torch placement relies on `Renderer.bounds` being current in edit mode.
- **Other gates** that rebuild the dungeon now also import the KayKit packs and add the renderer feature (idempotent, a few seconds after the first run).
