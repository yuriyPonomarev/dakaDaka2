## Exact scope

- Add an independent positive authored `AttributeCurveProfile.action` table with defaults `(1,.82),(6,.92),(10,1),(16,1.12),(22,1.20),(30,1.28)`. Existing piecewise evaluator validates/copies points. Existing builder persists the new serialized table without replacing authored points; no YAML assets are fabricated by the worker.
- `StatsComponent.Initialize` captures the action curve immutably. `ActionSpeedFactor` is evaluated from effective DEX; both equipment paths keep the initialized capture and increment existing versions. `EffectiveStatsSnapshot` stores its own value, so old captures remain unchanged and existing cache/version invalidation reaches new captures.
- Optional `IActionSpeedSource` is read from the registered authoritative entity. `PlayerRig` exposes its effective capture. This is an offline authority read seam; U3B must provide its server-owned equivalent. It is not proof of network combat acceptance. Entities without the interface use factor1. No factor enters any client intent; no intent/save/affix/attribute key schema changes.
- `ActionSpeedRules.Resolve` computes accepted windup, active, recovery, wall recoil and complete repeat interval exactly once at swing begin. Invalid/NaN/infinite/nonpositive factor uses1. Finite positive factors remain tunable; if their duration arithmetic becomes nonfinite, the accepted computation safely falls back to1. Active retains its .02s floor. Cooldown is divided by rate, retains its .1s floor, then existing .8 authority grace applies. Accepted repeat interval is `max(scaled/floored cooldown * grace, accepted timing total)`.
- Authority record/status freezes timing, sanitized accepted factor and repeat interval. Previous accepted interval is stored with its attack stamp and governs later attempts despite regear. Shared frozen-prior helper is used by melee, legacy SubmitAttack, projectile rate checks and WeaponCooldownRemaining. A different accepted attack stamp makes the old floor inapplicable. Ranged own cooldown, draw/reload and all skills are not action-scaled.
- MeleeCombat uses authority accepted timing and repeat interval; it does not infer an unscaled weapon fallback or apply action speed again. Weapon visuals receive the existing SwingTiming handoff. Client-only .02 windup/recovery and .05 wall-recoil extensions were removed; authority's actual active floor remains. WeaponVisualRig keeps only a division epsilon for wall recoil, so a short accepted recoil is not silently extended.
- Geometry, damage, turn/aim limits, combo order/multipliers and authored combo-window duration remain. Combo-window opening follows the accepted ActiveEnd. No broad HP/mana/remap/ability/affix/timing extension; both classes keep mana.

## Sampling/contact dependency review

`SwingGeometry.SampleCount` keeps its legacy overloads. New duration overload uses accepted active seconds for the aim-turn travel budget; slower swings therefore receive the turn samples their longer active phase requires. Translation probes remain unchanged. Count is capped before int conversion, preventing overflow/unbounded sample work for extreme finite durations; K remains within8..400.

The record freezes contact window as `acceptedActive * clamp01(authoredContactWindow / authoredActive)`. Processing uses acceptedActive/K for sampleDt. This preserves the authored normalized blade-path contact window, including when the .02s active floor binds. A contact window covering more than the whole active phase is equivalent to the whole active phase because pending contacts resolve at active end. The focused gate checks unchanged single body hits/damage and literal normalized1/15 windows for slow/fast cases, plus whole-phase resolution with the active floor.

## Intentional neutral client alignment

The previous local MeleeCombat input floor was `max(.1, weapon.cooldown, timing.Total)`; the authority already used its .8 grace with full-swing floor. Local input now follows the authority's accepted interval. This deliberately aligns the client with existing authority/enemy policy, rather than retuning authority grace:

| Literal neutral case | Old local input interval | Accepted authority/new local interval |
|---|---:|---:|
| Sword .24+.30+.30 with cooldown .92 | .92 | .84 |
| Same phases, cooldown2 | 2 | 1.6 |

Sword local input is about8.7% shorter; a purely cooldown-dominant neutral case can be20% shorter because the existing grace is .8. Both literals are explicitly covered by the focused gate; root approved this policy. Authority neutral/enemy behavior remains unchanged.
