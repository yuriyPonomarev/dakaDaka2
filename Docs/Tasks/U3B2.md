# U3B2 - production server-owned skill channel (active skills, slots 0/1)

Status: implemented, NOT compiled or run by the author (no Unity available). The local tester must compile and run everything below.

## What changed

Production channel (compiled in release builds)
- `NetPlayerRig.SkillIntentRpc(int slot, uint sequence, RpcParams)`: `[Rpc(SendTo.Server, InvokePermission = RpcInvokePermission.Everyone)]`, reliable ordered. Every RPC that must accept non-owner callers (the two hostile probes and this one) uses `InvokePermission` instead of `RequireOwnership`.
- Server admission (`Net/NetSkillServer.cs`) is identity-first: connection -> identity row -> NetworkObject reference equality. On any identity fault nothing about the victim is read. Then the per-connection `SkillIntentGate` (server monotonic clock), then `row.Rig.Skills.TryCastSlot(slot, out SkillRefusalCode)`.
- Feedback: `SkillResultRpc` (`SendTo.Owner`: accepted/refused + reason + mana + per-slot cooldown/duration), `SkillState` NetworkVariable (owner read, server write, published at most every 0.2 s when the 0.1-quantized state changes), `SkillVisualRpc` (`SendTo.NotOwner`, observers only, cosmetic). No client applies gameplay outcomes.
- Owner view: `NetOwnerSkillView` (replicated values only, IMGUI overlay outside batch mode, `Changed` event for a future HUD). Observers: `NetSkillCastFlash`.
- Client: `NetSkillSender` is the only skill code a client runs. `SkillCaster.Update` returns early when `NetRole.IsClientOnly`; `TryCastSlot` refuses with `ClientRole` there. Host keeps the local path; the host is never sent feedback RPCs and never disconnected, so there is no double cast.

Pure rules (assembly `Emberdelve.NetRules`)
- `SkillNetLimits.ActiveSlots = 2` is the one slot bound; `SkillCaster.ActiveSlotCapacity` and the gate both reference it (P6).
- `SkillIntentGate`: one sequence shared by both slots. Verdict order unchanged (existing tests hold). A `Redundant` verdict is deliberately absent: with one shared strictly increasing sequence, a duplicate is indistinguishable from a replay and is `Replay` (P7/F6). Invalid does not move the sequence; Flood consumes it. Sequence ceiling and clock bounds are rejected. A probation constructor starts with fewer tokens.
- `SkillAbuseControl`: `SkillRejectLedger` (token bucket over ALL rejects: Identity, Invalid, Replay, Flood; defaults burst 8, refill 1/s), disconnect when excess reaches the threshold (default 8), `NetLogThrottle` (1..3, powers of two, every 100th) and `SkillAbuseMemory` keyed by dev slot (case-insensitive, 120 s default window, 256 entries).
- Abuse policy: only rejects beyond the bucket allowance are "excess". Disconnect reason `skill abuse`. After a strike the same slot rejoining inside the window starts on probation: empty reject bucket, skill gate with 0 tokens, disconnect threshold halved per strike (min 1, 8 strikes cap). The slot is a dev identity, not authentication (known limit).
- Launch args: `-ember-net-skill-reject-burst`, `-ember-net-skill-reject-rate`, `-ember-net-skill-disconnect-after`, `-ember-net-skill-memory-seconds`.
- Scripts: `skill-cast` (production, all builds); `skill-proof` and `skill-abuse` (dev builds only, like `forge-owner`). `IsDevelopmentOnly` decides.

Fixes
- P9: `NetInputSender` uses real input only when it has no script and is not in batch mode.
- P11: `NetPlayerRig.FindProbeVictim()` (highest ServerPlayerId not owned) is used by both probes.
- P12: rule written in `Docs/Design/DND_PARITY.md` (empty Battle Cry costs mana, no min-target check).
- The dev `SkillIntentProofRpc` and the `SkillIntents` field of `NetIdentityTable` are gone (migrated to the production path).

## Decisions
1. Reject without reply: gate rejects get no response, so an abuser cannot learn anything or amplify traffic.
2. Aim is the rig pose from the last sanitized movement frame (movement is unreliable, skills reliable, so they are separate channels). Logged as `inputAgeTicks`.
3. Cooldown countdown between state updates is client display extrapolation of replicated values; mana is never simulated.
4. Gate uses `Time.realtimeSinceStartupAsDouble` on the server only; client timestamps are never trusted.

Expected values are derived at runtime by the gate, never hardcoded: warrior max mana = `AttributeRules.Derive(new AttributeSnapshot(cls.BaseAttributes), cls.AttributeBases).MaxMana` (70, not the authored 75); costs from `SkillData.EffectiveManaCost`; cooldowns from `EffectiveCooldown` (client display bounded by `SkillCooldownRules.MinimumMultiplier` 0.4 and curve max 1.2).

Scenario: server started with reject burst 8, refill 0, disconnect-after 8, memory 600.
- Client A (`skill-cast`): cast slot 0, same slot again at 0.4 s -> refused `Cooldown`, then slot 1 cast. Mana drops by exactly the derived costs; owner log equals the server `skill-cast` text; replicated `skill-view` matches; no client-side duplicate cast.
- Client B (`skill-abuse`): 3 forged-identity intents, valid seq 1, replay seq 1, invalid slot 9, 20 flood. Server counts identity=3 and disconnects with reason `skill abuse` at total = burst + threshold = 16. A observes exactly 2 visuals from B's valid cast; A is unaffected.
- B2 rejoins with slot `skl-b`: `skill-abuse probation` line (threshold 4, tokens 0). Second strike at total=4.
- Clean exits; forbidden patterns absent; static source checks (no identity-named RPC parameters, no `RequireOwnership` on skill RPCs, production RPCs outside the dev guard).

## Known limits / risks
- NGO spellings not verified without a compile: `InvokePermission = RpcInvokePermission.Everyone`, `SendTo.NotOwner`, `serializer.IsWriter`, `SerializeValue(ref string)`. If `InvokePermission` does not exist, fall back to `RequireOwnership = false` on the three RPCs (the gate's static check then needs the same update).
- A server dash causes an owner-prediction Ack mismatch and a snap (prediction does not know server-driven moves).
- Skill aim can lag the client's real aim by the input age.
- Slot-keyed memory is only as strong as the dev slot; real accounts are future work.
- Client HUD does not exist on clients (game master deactivated by NetSceneRoles); the IMGUI overlay is provisional.
- No melee/ranged over the wire (U3B3). Passive slots and consumables are out of scope.
- ROADMAP U3B row: U3B2 done pending local proof; U3B3 remains.
