## 7. Fixture findings for Codex (I changed nothing)

1. **Coverage gap the brief explicitly requires:** "malformed points / missing profile" for the CHA curve is covered
   nowhere. The 27 new cases test curve/duration arithmetic only and never call `TryCaptureInteraction` /
   `CaptureInteraction`; `EmberdelveAttributeCurveGate.cs` (48 `Check`/`Close` call sites) contains **zero** occurrences of
   "interaction". A 1-point table, non-increasing x, non-positive factor or null profile is untested for CHA timing while
   the identical action/movement cases are covered.
2. **Non-discriminating assertion:** `Close(_interactor.CapturedHoldDuration, 0f, "target loss clears capture")` (line 244).
   With the fixture's own `maximumDeltaTime = .05` ceiling the release decay removes 0.08/frame, so progress 0.15 → 0.07 → 0
   in two frames and `if (_holdProgress <= 0f) _holdDuration = 0f;` already cleared the capture before the deactivated chest
   is noticed; it would pass even if target loss cleared nothing. Needs the key still held (no decay branch) or a paired
   `CurrentTarget == null`.
3. **Not a full-window fit proof:** `preferredWidth <= rect.width + .1f` (line 267) runs on an isolated 346 px
   `CharacterStatsView` host under `-batchmode -nographics`, where Text preferred metrics can be 0 with no graphics device
   (0 ≤ 168.1 passes trivially). The brief's real requirement — the actual inventory character pane and equipment labels at
   supported window sizes — is **not** covered by this gate and remains outstanding; an isolated host alone would not
   satisfy it either.
4. **Input restore is structural, not asserted:** the gate restores `InputSystem.settings` in `Cleanup()`/`OnDestroy()` but
   never asserts `ReferenceEquals(InputSystem.settings, original)` afterwards the way `EmberdelveDrawSpeedGate` does.
5. Secondary observations: `CheckPane` builds a fresh host per call (4 per run), destroyed only in `Cleanup`, so the pane
   assertions never touch the real `InventoryScreenController` (that is `RunInventoryUiFlow`'s job); the sealed-refusal probe
   waits `while (Time.time < until)` with no wall-clock bound (≥ 50 frames at the .05 ceiling, ≈ 8.3 s wall on a 6 fps
   unfocused Editor — the slowest loop in the fixture); the damage probe calls `HealthComponent.ApplyDamage` directly (as
   the draw gate does), so armour/DamageResolver mitigation is not exercised although `Damaged` always fires.
6. Positive controls confirmed statically: `Apply()` clones the class **and** its profile before the fixture mutates
   `ownedProfile.interaction`, and `Flow()` ends with an `EditorJsonUtility.ToJson` comparison of both class assets, the
   shared profile and the ring definition — a shared-definition leak would be caught. `Cleanup()` restores
   `Time.maximumDeltaTime` (guarded by `_ownsMaximumDeltaTime`), removes the added `Keyboard`, re-points
   `InputSystem.settings`, destroys the `HideFlags.HideAndDontSave` clone and every tracked fixture object, and is idempotent
   through `OnDestroy`. `Time.timeScale` is never touched.
