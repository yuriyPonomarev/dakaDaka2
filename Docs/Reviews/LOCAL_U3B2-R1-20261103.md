### New observations for Codex (reported, not repaired)

1. **Abuse memory is per-server-process, not persistent.** `SkillAbuseMemory` lives inside the `NetSkillServer` instance and is cleared by `Dispose()` on shutdown. The code comment says it "survives the connection AND the actor" — it does not survive a server restart. A hostile client that waits for a server restart escapes probation entirely. Worth stating as a limit in `Docs/NETWORK_PLAY.md` / `Docs/Tasks/U3B2.md` alongside the existing "slot is a dev identity, not authentication" caveat.
2. **Slot resolution at first touch decides probation.** `NetSkillServer.Receive` calls `GetConn(sender, now, null)`; if a skill intent is processed before the row is admitted, the slot comes from `NetServer.SlotOfClient` (table, then `_approved`). If neither knows it yet, the `Conn` is created with `slot=""`, so `_memory.StrikesFor("")` returns 0 → full allowance and base threshold; `OnAdmitted` backfills `Conn.Slot` but not the already-built ledger/gate, and `RecordDisconnect("")` returns 0 (no strike remembered). Not reachable in this gate (RPCs are delivered on spawned objects after approval) and not exercised by any current gate; low severity, but the probation guarantee is conditional on first-touch slot resolution.
3. **Host-no-double-cast is proven by source, not by a live host run in this job.** `NetPlayerRig.OnNetworkSpawn` sets `Role = HostPlayer` for the host's own player and only `Role == Owner` gets `NetSkillSender`/`NetOwnerSkillView`; `NetRole.IsClientOnly` is false for a host so `SkillCaster` still casts locally; `NetSkillServer.Receive` returns before feedback when `sender == NetworkManager.ServerClientId`, and `EndConnection` never disconnects the host (`host=1 (not disconnected)`). The NetSkill scenario is dedicated-server + 2 clients, so this remains an inspection result; a host-with-skills process check is still open (the NetFinal gate samples a host launch but does not cast skills on it).
4. **Client sequence is consumed before delivery.** `NetSkillSender.TryRequest` increments `_sequence` before calling `SkillIntentRpc`. If the RPC is not delivered (connection lost between the `IsSpawned` check and the send), the number is spent. The next request after a reconnect uses a fresh sender and a fresh connection gate, so this cannot produce a `Replay`; a gap stays inside `MaxSequenceJump = 64`. No defect claimed — noted because it is the kind of thing a future real-input sender must respect.
5. **Gate coverage of the new launch arguments** is limited to the four values the NetSkill gate passes and asserts (`rejectBurst/rejectRefill/disconnectAfter/memorySeconds` echoed by the server's own policy line). The argument-validation branches in `NetLaunchArgs` (ranges, `invalid skill reject burst …` errors) are covered only by the EditMode fixtures added in U3B2, which were not re-executed in this job (see §1).
