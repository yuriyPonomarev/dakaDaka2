WIS band from the saved profile: `1→.70, 6→.90, 8→.95, 10→1.00, 11→1.02, 13→1.06, 14→1.08, 16→1.12,
17→1.14, 18→1.16, 20→1.20, 22→1.24, 24→1.28, 30→1.40` (all inside the `.6…1.4` sanitize band).

**Provenance of the removed literal, recorded for audit:** `0.96f` is exactly
`AttributeRules.AbilityEffectScale(CHA 8)` = `clamp(1 + .04·floor((8−10)/2), .6, 1.4)` = `clamp(1 − .04)`
= `0.96` — the pre-D4d1 CHA definition. Under the current definition (`StatsComponent.GetAbilityEffectScale()`
evaluates the captured `skillPower` curve at `SixAttribute.Wisdom`) `0.96` is **unreachable from this
fixture** (WIS14 → 1.08). Warrior CHA10 would also have been `1.00` under the old definition, which is why
the new `before == 1f` conjunct is a valid but *not* CHA-discriminating anchor.

**Honest limitation of the fixture (unchanged by this fix, still open for Codex if wanted):** the fixture
swaps the whole class, so WIS 10→14 **and** CHA 10→8 change together. It is not a pure-CHA negative
control; the `WIS14 → 1.08` literal is what pins the definition. A genuine CHA-only control would need a
fixture that changes CHA while WIS stays fixed.
