## 5 The failure — `EmberdelveEffectiveStatsGate` (defect for Codex; not repaired)

**Reproduction**

```
& ./Tools/Run-EmberdelveGates.ps1 -ProjectPath . `
    -Methods @('Emberdelve.EditorTools.EmberdelveEffectiveStatsGate.Run') `
    -OutputDirectory Logs/local-testing/D4d1-20261102/gatesB-040842 -TimeoutSeconds 1200
```

`exit=1`, `[Emberdelve][EffectiveStats] FAIL checks=30 failures=1`, raw log
`gatesB-040842/Emberdelve.EditorTools.EmberdelveEffectiveStatsGate.Run.log` (454 lines):

```
L395: [EffectiveStats] mismatch: CHA mutation invalidates the old capture and updates the public snapshot-backed ability scale
L403: …EmberdelveEffectiveStatsGate:CheckRigCache (…) at Assets/Emberdelve/Editor/EmberdelveEffectiveStatsGate.cs:248
L404: …EmberdelveEffectiveStatsGate:Run () at Assets/Emberdelve/Editor/EmberdelveEffectiveStatsGate.cs:181
L408: [Emberdelve][EffectiveStats] FAIL checks=30 failures=1
```

No `error CS`, no exception, no other mismatch in that log; the other 29 checks of the gate ran.

**The assertion** (`EmberdelveEffectiveStatsGate.cs:242-251`, inside `CheckRigCache`):

```csharp
float abilityScaleBeforeAttributeMutation = rig.EffectiveStats.AbilityEffectScale; // attributes initialized from WARRIOR
attributes.Initialize(archer);
EffectiveStatsSnapshot afterAttributeMutation = rig.EffectiveStats;
check(Mathf.Approximately(afterAttributeMutation.AbilityEffectScale, 0.96f)          // <-- fails
   && Mathf.Approximately(rig.AbilityEffectScale, afterAttributeMutation.AbilityEffectScale)
   && !Mathf.Approximately(abilityScaleBeforeAttributeMutation, afterAttributeMutation.AbilityEffectScale),
   "CHA mutation invalidates the old capture and updates the public snapshot-backed ability scale");
```

**Inputs and likely cause.** The fixture re-initializes the same `StatsComponent` from the Warrior class
(WIS10 → captured power **1.00**) to the Archer class (WIS14 → captured power **1.08**). `0.96f` is the
historical CHA meaning of the query — Archer CHA8 → modifier −1 → `clamp(1 + 0.04·(−1), .6, 1.4) = 0.96`
from `AttributeRules.AbilityEffectScale`, which `StatsComponent.GetAbilityEffectScale()` no longer calls
(`StatsComponent.cs:385-395` now evaluates the captured `skillPower` curve at `SixAttribute.Wisdom`).
So this gate's fixture was **not migrated** in the integration (the file is absent from `git diff HEAD`),
while `AttributeSkill`, `CloakSlot` and `RolledAttributes` were.

The other two conjuncts are satisfied — `rig.AbilityEffectScale` mirrors the new snapshot, and
`1.00 ≠ 1.08` — so the capture-invalidation semantics the check exists to prove still hold; only the
literal (and the label's "CHA" wording) is stale. Independently derived replacement literals, for Codex
to choose and justify, **not applied by me**: expected `1.08f` (Archer WIS14) with the "before" value
being Warrior WIS10 → `1.00f`. A stronger version would keep a genuine CHA-only negative control here
(CHA changes while power stays 1), which this fixture cannot express by swapping classes alone, because
warrior→archer changes WIS as well.

**Consequence:** the assigned "no failures" condition for the requested gate set is **not met**. I did not
edit the assertion, its tolerance, or its inputs, and I did not re-run the gate expecting a different
result.
