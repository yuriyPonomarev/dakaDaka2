### 5.1 Fixture defect (Codex repair item)

`ReviewD4c1.Measure` calls `screen.Rebuild()` and then counts `root.GetComponentsInChildren<Text>(true)`
by name prefix. `InventoryScreenController.Rebuild()` destroys the previous equipment labels, but Unity
defers `Object.Destroy` to the end of the frame, so the outgoing labels are still children and are
counted together with the new ones:

- `Measure` (1 rebuild) → 26 = 13 live + 13 pending-destroy, each duplicate pair at **identical**
  screen rectangles (e.g. `EquipLabel_Weapon` twice at 1458,953 at 2560x1440).
- `Prepare` (4 rebuilds in one frame: `Open()`, tab click, `Rebuild()`, then `Measure()`'s own) → 52 = 4×13.
- A no-rebuild probe in the same Play session (`eval-ui-live-counts.txt`) reports
  **`equipLive=13`, `statTexts=28`, `canvases=1`** — the live UI has exactly 13 equipment labels.

So the assertion can never pass as written. Repair belongs to Codex (count unique slot names, or count
after a frame boundary, or exclude the objects Rebuild queued for destruction). This is a harness
counting artifact, **not** evidence of duplicated or clipped UI.
