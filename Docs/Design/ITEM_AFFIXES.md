# Fixed item properties and random affixes — user amendment

The user requires both static and random attributes on armour, boots, cloaks etc. This applies to functional equipment stats, not decorative names. This extends ATTRIBUTES.md and DESIGN.md. Complete M1D after M1C and before M1B.

Each ItemDefinition is an immutable base archetype: fixed armour/damage, size, equipment slot, base_modifiers (extend allowlist if necessary) and fixed attribute_bonuses for the six scores. Add back/cloak equipment slot; include at least two cloak definitions and boots. A dropped ItemInstance gets its own stable UID, rarity and server-rolled affixes; same base item can have different bonuses on different drops. Fixed values do not disappear when random properties are added.

AffixDefinition(Resource): id, display_name, stat_key, min_value, max_value, step, weight, allowed_categories; .tres data under assets/data/affixes. Allowlisted keys cover strength/dexterity/constitution/intelligence/wisdom/charisma, armor, max_health, max_mana, move_speed, melee_damage, projectile_damage, mana_regen. Attribute values are integers; other steps configured. Use bounded starter ranges (attribute +1..3, armour +1..6, HP +5..15, mana +5..15, speed +0.03..0.12 m/s, damage +1..4, regen +0.1..0.4/s). No client-provided arbitrary stat names. Profiles may restrict which affixes can roll on boots, cloak, armour, weapon etc.

Common: fixed stats, 0 affixes. Uncommon: fixed stats, 1 affix. Rare: fixed stats, 2 distinct affixes. LootRoller uses supplied RandomNumberGenerator/server RNG and allowlisted rarity. Weighted sampling without replacement; no duplicate stat keys on one item. Final affixes persist as [{id, stat_key, value}] in the instance. Do not store mutable/random results in ItemDefinition. Stackable consumables/currency cannot silently merge different-affix equipment. Identical seeds are deterministic for tests, normal server raid seeds differ.

Inventory snapshots/persistence include rarity and rolled affixes. Unknown keys, wrong ID/key pair, nonfinite/out-of-range/off-step values, disallowed category, duplicated affix, too many affixes or impossible rarity combination are rejected atomically. A client cannot choose item rolls or submit arbitrary stats; transfer references UID and server-held instance. Do not reroll during transfer/equip/unequip/restore. Fixed starter kits use explicit common rarity unless specified otherwise.

Effective equipment bonus = base fixed attribute bonuses/modifiers + rolled affixes. Recompute stats from the actor's pristine class data plus all currently equipped instances once; never accumulate on repeated equips. HP/mana capacity changes do not create free current-pool refill. Use these bonuses in real movement, damage, regeneration and health. UI/tooltips separate fixed properties from random affixes and show rarity colour; character panel shows effective six scores and derived values. Cloak uses back slot and can contribute stats like other armour.

Tests: deterministic same seed, multiple seeds give different valid properties, count/uniqueness per rarity, fixed stats preserved with random bonuses, base resources unchanged, save/restore exact rolled values, invalid/tampered affix rejection, equip+unequip roundtrip no accumulation, two players racing for one chest instance cannot duplicate its UID. Item instance production belongs on authoritative server.

## D3a addendum: the rarity ladder

The three tiers above are the lower half of a seven-tier ladder (decision C7 in `DND_PARITY.md`): Poor, Common, Uncommon, Rare, Epic, Legendary, Unique, with 0, 0, 1, 2, 3, 4 and 5 rolled affixes. There is no Artifact tier. Stored ints never change meaning: Common 0, Uncommon 1, Rare 2, Epic 3, Legendary 4, Unique 5, Poor 6 (Poor ranks below Common, so a stored int is an identity and never an order; sort and compare through the tier ordinal Poor 0 .. Unique 6). The distinct-key rule, the rolled-value rules and "no reroll on transfer/equip/restore" apply unchanged to every tier. The shipped pool has at least 10 distinct keys for every gear family, so Unique (5) is always satisfiable; if a catalog or table cannot supply a tier's count the roll or the table is refused with a reason, the count is never lowered. Fixed (primary) stats of the base definition are never rolled and never change with rarity. Snapshots are schema version 2; version 1 saves migrate on load. See `Docs/Tasks/D3a.md`.
