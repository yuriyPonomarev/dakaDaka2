3. STASH-01 — ТЕКУЩАЯ РЕАЛИЗАЦИЯ

Цикл: выбрать класс -> PREPARE RAID -> подготовить экипировку/сумку, купить/продать -> рейд -> эвакуация сохраняет предметы -> смерть/незавершённый рейд теряет только взятое с собой -> склад и золото сохраняются между запусками.

Реализовано:
- отдельный локальный профиль каждого класса;
- склад 12x20, сумка 10x5;
- стартовый комплект и 150 золота один раз на профиль;
- сохранение UID и характеристик предметов;
- покупки идут на склад;
- первый торговец продаёт базовые предметы нашего каталога и покупает добычу;
- SQUIRE / BASE WEAPONS выдаёт бесплатное базовое оружие в пустые слоты, не заменяя надетые вещи;
- до выноса из рейда бесплатное оружие нельзя отправить на склад или продать с прибылью;
- ПКМ надевает/снимает; Shift+ПКМ переносит; перетаскивание в точную ячейку; изображение предмета следует за курсором; Escape отменяет выбор;
- экипировка и сумка слева, торговец посередине, склад справа;
- миграция чернового склада 10x12 в 12x20 без удаления предметов.

Сохранения: Application.persistentDataPath/OfflineProfiles/<classId>.json.
Для Editor/Development Build: --ember-profile-dir "<отдельная папка>".

Транзакция: копирование -> валидация -> запись -> публикация. Используются ревизии, checksum, временный файл, backup, файловые блокировки. Перед рейдом комплект резервируется: убирается из доступного профиля, записывается activeRaid. После сбоя процесса комплект считается потерянным, склад остаётся. Повторная эвакуация с одним id не дублирует награды. Ошибки записи не должны менять опубликованное состояние. Повреждённый файл не сбрасывается молча.
